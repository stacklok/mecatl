# Offline external consumer proof

From the checkout, run `scripts/prove-external-persistence.sh .scratch/external-proof-N` (or append `-race`). Each run requires a **new** output directory. The helper packages current adapter source as a `v0.1.0-dev` archive; support, driver, and engine resolve at their real pinned revisions through cached download artifacts. It creates a fresh, isolated `GOMODCACHE` (and an output-local `GOCACHE` unless the caller sets one under `.scratch`), turns the workspace and sumdb off, and tests this unrelated consumer without `replace`. The ordinary module suite separately tests current support and driver code. Missing cached artifacts fail rather than contacting a service. `graph.txt` and `engine-graph.txt` are saved in the output directory; the latter must not include host, Redis, or gRPC modules. The checkout's `adapters/go.mod` and `adapters/go.sum` continue to require and verify the real pinned revisions. Never commit candidate zip checksums as published release sums.

This fixture is a portability test, not an authorization or read-only mount guarantee. JSONL `New` probes/writes directory metadata; some JSONL reads take family locks or rebuild catalogs. Redis `New` can initialize missing metadata/lineage markers; ordinary reads do not establish real Redis ACL compatibility (miniredis cannot prove that), and incomplete ACLs can make `List` omit denied rows. The public gRPC wrappers add no authentication and the caller owns both client connections. A gap is explicit only when `AppendGap` succeeds: an unknown empty stream cannot prove that no append was lost. Native `Delete` invalidates old cursors; arbitrary out-of-band Redis `XTRIM` without generation change is not detected. No host application writer is imported here; host-to-external-reader wiring remains a separate integration boundary.
