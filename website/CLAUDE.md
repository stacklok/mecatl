# website/ — Docusaurus site for mecatl.dev

The Docusaurus infra lives here. **Content does not.** All `.md` doc files live in
`../user-docs/` (repo root `user-docs/`). The site simply points its docs plugin at
that directory:

```ts
// docusaurus.config.ts
docs: { path: '../user-docs', routeBasePath: '/docs', ... }
```

Do not put new docs in `website/`. Edit `user-docs/`.

---

## Commands

Use the root Taskfile's `site:` namespace — not `npm run` from inside this directory:

```sh
task site:dev       # start dev server at http://localhost:3001 (background)
task site:build     # full build into website/build/ (catches broken links)
task site:stop      # stop the dev server
task site:typecheck # TypeScript check
task site:clear     # wipe .docusaurus/ and build/
```

`task site:build` is the authoritative broken-link check. The site is configured with
`onBrokenLinks: 'throw'`, so a build failure means a link is broken — not a warning.

## Link convention

Use **content-root-relative `.md` paths** for all cross-document links. These survive
slug renames, render correctly in GitHub's markdown preview, and are portable if
`routeBasePath` ever changes.

### Pattern

```markdown
[The agent loop](/what-you-get/agent-loop.md)
[Overview](/extension-points/index.md)
[Cloud-native kit](/cloud-native-kit.md)
```

The leading `/` resolves from the docs content root (`user-docs/`), not the site root.
Docusaurus strips the `.md` extension when building URLs.

### For same-directory siblings, relative `.md` is fine

```markdown
<!-- inside getting-started/demo.md -->
[Deployment decision](./deployment-decision.md)
```

### What NOT to use

| Pattern | Problem |
|---------|---------|
| `/docs/what-you-get/agent-loop` | Site-root absolute — breaks if `routeBasePath` changes; `.md` omitted so GitHub can't preview |
| `../what-you-get/agent-loop.md` | Cross-section relative paths have a known Docusaurus v3 resolution bug with `index.md` files; use content-root-relative instead |
| `what-you-get/agent-loop.md` (no leading `/`) | Resolves relative to current file — fine within a section, fragile across sections |

### Why cross-section relative paths break

Docusaurus v3 resolves `../` traversals from `index.md` files based on the *folder*
location rather than the *file* location, causing the traversal to land one level too
high. Using content-root-relative paths (leading `/`) sidesteps this entirely.

## Stubs for unwritten sections

`onBrokenLinks: 'throw'` means you **cannot link to a doc that doesn't exist yet**.
Before adding a link to a planned-but-not-yet-written doc, create a stub:

```markdown
---
sidebar_position: 1
title: My planned page
---

:::note[Coming soon]

This page is being written. Check back soon.

:::
```

Any new section directory also needs its `index.md` stub before `intro.md` (or any
other doc) can link to it.

## Sidebar

The sidebar is fully autogenerated from the `user-docs/` directory structure. Control
order with `sidebar_position` in frontmatter. No manual sidebar editing is needed or
wanted — `sidebars.ts` is intentionally minimal.

## Config notes

- **Dark-only.** `colorMode.disableSwitch: true`, `defaultMode: 'dark'`. Don't use
  assets that only work on a light background.
- **Mermaid.** `@docusaurus/theme-mermaid` is installed. Use `mermaid` fenced code
  blocks freely — they render as diagrams.
- **Admonitions.** Custom titles require bracket syntax: `:::note[My Title]`. Blank
  lines inside the block are required. See the global `~/.claude/CLAUDE.md` for the
  full rule.
- **Search.** `@easyops-cn/docusaurus-search-local` is wired up. It indexes `user-docs/`
  automatically; no config needed for new pages.

## Writing user-docs

When authoring new pages in `user-docs/`, the primary source material is:

- `docs/architecture/*.md` — behavioral descriptions of each subsystem
- `docs/usage/*.md` — operator flags, config, and worked examples
- `docs/adr/*.md` — the *why* behind each design decision

Do not write from `AGENTS.md` / `CLAUDE.md` directly — those are internal contracts
with dense implementation detail. Synthesize from the architecture and usage docs,
which are already written at the right level of abstraction.
