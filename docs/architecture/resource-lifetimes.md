# Resource lifetimes and restart fidelity

> Part of the [mecatl architecture guide](../architecture.md).

This page is the living inventory of every resource the harness allocates whose
lifetime outlives a single tool call, and of every piece of live run or session state
that loading a session snapshot does not rebuild. Each row names the owner, how the
resource is cleaned up, and what a restarted process does with it. **Any change that adds
a resource outliving a call must add a row to [Resources that outlive a call](#resources-that-outlive-a-call)
in the same change**; any change that adds live state a restart cannot rebuild from the
snapshot must add a row to [Restart fidelity](#restart-fidelity).

**Prerequisites:** [observability & persistence](observability.md) — the stores, event
log, and snapshot format these rows refer to.

**Follow-on:** [deployment & hardening](deployment-and-hardening.md) — leasing, drain,
and multi-replica behaviour that decides when restart state matters.

## Restart-state vocabulary

- **reconstructible** — rebuilt from configuration, disk, or durable state on the next Build or run entry.
- **persisted** — the durable artifact survives and is reloaded.
- **client-owned** — the client or application holds the position or handle and reattaches; the server keeps nothing.
- **reset-by-design** — lost on restart, deliberately, with documented fail-closed behaviour.
- **lost** — gone on restart with no recovery path; listed so the gap stays visible.

For restart fidelity, the decisions are **persist-in-snapshot** (an additive snapshot
field), **persisted** (durable outside the snapshot), **derive** (recomputed from persisted
state), **fix-via-event-log** (replayed from the durable event log), and **reset-by-design**.

## Constraints that still apply

- **Memory scope is the deployment.** The memory driver protocol carries no tenant,
  principal, session, or namespace field (`contracts/proto/mecatl/driver/v1/memory_store.proto`),
  so the configured `--memory-dir` or `--memory-store-url` endpoint is the memory scope for
  every session in the process. A deployment that needs per-tenant memory runs one memory
  endpoint per tenant. Do not add per-session memory assumptions without a protocol change.
- **Single writer without a lease.** Session leasing (`--session-lease-dir`,
  `--session-lease-k8s-namespace`, `--session-lease-url`) enforces one writer per session
  across replicas. Without a lease backend, run exclusion is in-process only and the
  driver `Save` is last-write-wins, so routing each session to one process remains the
  deployer's responsibility. See [deployment & hardening](deployment-and-hardening.md#multi-replica-affinity-correlation-and-single-writer-enforcement).

| Staged learning proposals, materialization manifests, and promotion linkage | `reflectionstore` document (`internal/adapter/reflectionstore/store.go`) with partitioned proposal records and immutable manifests; resulting memory revisions carry `MemorySource.ProposalID` (`engine/tool/memorylifecycle.go`) | The exact manifest and proposal status reload; manifest citations are validated against the stored manifest. Old records keep `reflection-evidence/legacy-v0` semantics. A crash between memory write and proposal finalization leaves status `promoting` for reconciliation against the memory revision's proposal id. | **persisted**: proposal store and memory store are each durable; reconciliation closes the cross-store crash window without a distributed transaction. |
| Reflection queue, running jobs, and completion receipts | `reflectionCoordinator` queues, running/pending maps, and receipts (`internal/app/reflection_coordinator.go`) | Lost, including queued or running extraction; already staged proposals and memory revisions survive. | **reset-by-design**: no retrospective sweep; an explicit retry re-materializes from durable sources, and deterministic proposal IDs converge on an existing proposal. |
| Agent-owned skill lifecycle and proposal linkage | `skillstore.Store` (`internal/adapter/skillstore/store.go`): flocked `manifest.json` plus immutable content-addressed `SKILL.md` files; proposal linkage in `reflectionstore` | Versions, lifecycle states, history, and active selection reload. A crash after draft persistence but before linkage leaves an inactive draft; a retry converges on the same skill. | **persisted**: both stores are independently atomic; no startup sweep and no automatic activation. |
| Automatic-learning reservations, cooldowns, dedupe, and count windows | `automaticstore` (`internal/adapter/automaticstore/store.go`, `automatic-admission.json`) or the `grpcdriver.AutomaticAdmissionLedger` driver; reconciled by `internal/app/automatic_reservation_reconciliation.go` | Charges, fences, cooldown, and dedupe state reload. A Build-owned worker re-fences expired held reservations and settles each as retained or reclaimed against the linked attempt. | **persisted**: retention capped at 512 records globally and 128 per principal (`engine/learning/automatic_ledger.go`). |
| Redis session metadata index and event-log generations | `mecatl:session-metadata:*` keys (`adapters/redisstore/metadata_index.go`) and `mecatl:events-gen:*` keys (`adapters/redisstore/cursoreventlog.go`) | Index and generations reload; malformed or inconsistent records fail validation. | **persisted**: fail closed; no inventory scan, adoption, or migration path. |
| Manual dream pending plans and decision receipts | `dreamReviewCoordinator.records` (`internal/app/dream_review.go`), bounded with TTL eviction | Every pending plan and receipt is lost, including on a different replica; the operator must regenerate (another provider call). | **reset-by-design**: mutation material is never persisted or accepted from the client; completed memory revisions remain the store's truth. |
| Pending (un-drained) operator steer | Run-scoped single-slot `steerInbox` (`engine/agent/steer.go`) holding text, media parts, and message id; never written to the store | A parked steer dies with its run (crash, cancel, abandon). A steer drained at a turn boundary or by `closeSteerDrained` is ordinary recorded user history. `finishTurnNoTools` keeps a live run going while a steer is parked, so loss is crash/cancel-only. | **reset-by-design**: best-effort mid-run input, not state of record. |
| Failed-step retry intent | `Session.PrepareFailedStepRetry`/`FailedStepRetryPending` (`engine/session/session.go`); `RetryPending*` fields on `sessnap.Snapshot`; `EvModelRetry` with `ModelRetryPayload` folded by `eventsource` | Persisted before `Engine.RetryFailedStep` launches. Crash before turn start restores idle plus pending; afterwards running plus pending. Cancellation clears the intent. | **persist-in-snapshot**: marker fields plus a structured `model.retry` event; whole prompts are not persisted. |
| Relay-buffered message/reasoning deltas | `RunEventRecorder` (`internal/adapter/server/event_recorder.go`): one message and one reasoning accumulator, each capped at 1 MiB | Pending chunks are lost; a failed append is treated as a gap rather than retried. Appended chunks are in the EventLog; the snapshot stays authoritative for completed turns. | **reset-by-design**: bounded memory; clients still receive original chunks live. |
| Debug-session kind, target lineage, and evidence handles | `session.Session.Kind`, `SessionRelationship.DebugTargetID` (`engine/session/kind.go`), and `DebugTargetFingerprint` (`engine/session/session.go`) round-tripped by sessnap and every store; lineage indexes in `adapters/jsonlstore/lineage.go` and `adapters/redisstore/lineage.go`; handles are deterministic hashes with no server state | The debug conversation and exact target binding reload. `Service.rehydrateSession` rebuilds only through `DebugSessionEngine`; invalid metadata, a missing factory, or target deletion/reuse fails closed. EventLog evidence survives only within configured retention. | **persisted**: existing snapshot, index, and events; the engine and handles are derived. |
| Worktree selector key and issued selectors | 32-byte random key generated in `internal/app/build.go` and held by `server.WorktreeSelectorIssuer` (`internal/adapter/server/worktree_selector.go`); no selector registry | The key changes, invalidating every outstanding selector; clients relist worktrees. | **reset-by-design**: selectors are not persisted anywhere; matching recomputes against current inventory. |
| Session-lease local validity and lost-owner state | `Service.heldLeases` and `Service.lostOwnership` (`internal/adapter/server/service.go`), `SessionMutationCapability.states` (`internal/adapter/server/mutation_capability.go`); durable awaiting truth is `sessnap.Snapshot.Pending` | Local holds, lost-owner denials, and run registry are lost. A successor acts only after acquiring the backend lease, then reloads the snapshot: `running` is repaired through `Abandon`; `awaiting` keeps the exact pending ask. | **reset-by-design**: local lease authority comes only from fresh lease acquisition; the snapshot already persists state and pending ask. |
| Durable learning-attempt lifecycle | `learning.AttemptRepository` (`engine/learning/attempt_repository.go`) records with deterministic IDs; driven by `attemptWorker` (`internal/app/attempt_worker.go`) | Queued, running, and terminal attempts reload with claim generation and checkpoints. The worker rediscovers queued and expired-claim records and resumes; transient setup failure backs off and ends `retry_exhausted` after 3 claims by default. | **persisted**: re-driven from the repository; coordinator and receipt state are not authority. |
| Session-scoped MCP broker binding and parked authorization | Snapshot persists `session.Session.ExternalBinding` and `PendingAuthorization`; the broker runtime (`internal/adapter/mcpbroker/runtime.go`) holds grants, tokens, callbacks, and timers in memory | The binding is `bindingPrefix + "." + generation`, with a random per-process prefix, so a restored binding is always stale after restart. Broker authority and timers are lost; a parked call is paired as interrupted and never replayed. `rebindBrokerAttachment` (`internal/adapter/server/mcp_broker.go`) adopts a fresh incarnation only before the first prompt. | **persist-in-snapshot**: pending authorization is durable; runtime authority resets and control paths fail closed. |
| Workspace-enrollment outer correlation | Snapshot persists `PendingWorkspaceEnrollment` (`engine/session/workspace_enrollment.go`); mecatl's callback/incarnation mapping is process-local; ToolHive's own storage holds inner authorization records | The outer correlation is lost, also on a wrong replica. Rebinding a pre-prompt session discards the old pending enrollment and allows a fresh one; it never searches ToolHive storage to resume. | **reset-by-design**: the aggregate's pending record is persisted, the outer correlation is not, and inner recovery is never inferred. |
| Prompt-free exact-ask handoff and resumed-run lifecycle | Snapshot persists `StateAwaiting`, `RunID`, `PendingAsk`, mode, and `EnvironmentRef`; plan asks resolve through `Service.ResolvePlanAsk` (`internal/adapter/server/exact_plan_ask.go`), which holds a process-local `planContinuation` | Local execution and join bookkeeping are lost; the last awaiting or terminal snapshot survives. An accepting replica acquires the lease, reloads, and revalidates run, state, and ask before resuming. A plan allow accepted before process loss is not proof that the continuation ran. | **persist-in-snapshot**: existing fields, reconstructed under a fresh lease. On shutdown a persisted awaiting point is preserved (`preserveAwaiting`); otherwise cancellation is persisted. |
| Mecatui rejected admission submission | `admissionSubmission` on `ui.Model` (`cmd/mecatui/ui/admission.go`), keyed by session ID and stream generation | A client restart loses the prepared text, media, and staging; the server transcript is unchanged because admission rejected before execution. | **reset-by-design**: client-only; retry is explicit. No snapshot, event, or transport change. |
| Harness-context source bindings | `harnessCommandResolver` (`internal/app/harness_context.go`): Build-local registrations, process bindings, and per-session binding entries with ref counts and retirement | Bindings and bookkeeping are lost, not session history. Resumed sessions resolve the currently configured sources for their owner and profile. | **reset-by-design**: current configuration is authoritative on rebind; nothing about the source is persisted, so config changes can change resumed context. |
| Experimental Kubernetes execution environment | Snapshot persists `EnvironmentRef`; the `ExecutionEnvironment` resource status and retained PVC hold provider identity, operation state, and workspace (`internal/adapter/executioncontroller/controller.go`); grants and client transports are in memory | The session reattaches exactly through the provider. The controller rebuilds its queue from informers. An active operation whose holder lease has expired is marked fence-unknown with its identity retained; completion is never inferred. Grants and transports reset. | **persist-in-snapshot**: plus external Kubernetes state; live workspace, controller queue, and transports are derived or reset. |
| Repository-scoped local microVM placement and boot record | `microvm.RepositoryVMRegistry` (`environment/microvm/repository_lifecycle.go`): owner/repository-keyed versioned JSON record, private rootfs, retained artifacts, and launch-attempt records | Placement reloads. A healthy same-daemon boot is reused; otherwise the old runner is reconciled before a new boot. Linux terminates via exact pidfd; Darwin never signals a stored PID and requires operator recovery if a historical runner stays locked. Missing, malformed, or uncertain state fails without replacement or deletion. | **persisted**: flock-serialized, fsync plus atomic rename; boot is reconstructed. |
| Repository child fork base and merge synchronization | `RepositoryAttachmentManager` (`environment/microvm/repository_attachment.go`): in-memory parent ref and `forkBase` per entry, and `mergeMu` | Guest handles, fork parentage, and merge lock are lost. Persisted attachment identity still supports status, delete, and reattach, but the restarted process cannot merge the child. | **reset-by-design**: attachment identity persists; fork relationship and merge authority do not. Malformed fork responses never trigger automatic deletion. |
| Repository logical-attachment inventory and dirty retention | Host-only versioned records under the repository's `attachments/` directory (`environment/microvm/repository_attachment_store.go`); the manager map is derived | Live guest registrations and Workspace handles are lost; status/delete identity reloads without booting. A dirty retained worktree stays available for recovery or cleanup. | **persisted**: fsync, atomic rename, and directory fsync outside the guest export; malformed, symlinked, duplicate, or path-inconsistent records are rejected. |
