# ADR 0376 - Target-scoped AGENTS instruction hierarchy

- Status: Proposed amendment to merged base plan; technical contracts selected here for human review, not approved or implemented
- Date: 2026-10-06
- Scope: project-instruction applicability, admitted-source mapping, and ephemeral context
- Supersedes: proposed partial supersession of [ADR 0359](0359-harness-context-source-authority.md)'s root-only discovery and [ADR 0043](0043-ephemeral-turn0-instruction-fragments.md)'s once-per-run project guidance
- Superseded by: none

## Context

[AGENTS.md](https://agents.md/) describes nested guidance and nearest-file conflict precedence, but does not require live refresh or prescribe discovery budgets. The [Codex AGENTS guide](https://developers.openai.com/codex/guides/agents-md/) documents a configurable *combined* default of 32 KiB and a 64 KiB example; Mecatl's 64 KiB default is the operator's choice, not Codex's default. [Claude's memory guidance](https://code.claude.com/docs/en/memory) describes lazy loading and parent-worktree guidance, relevant prior art for the source-mapping choice rather than authority for a child checkout. User instructions outrank repository guidance, subject to Mecatl's higher-priority safety and tool authorization. [Issue #2090](https://github.com/stacklok/mecatl/issues/2090) cites upstream commit `d001185d792eb6402a58e4cbef1c228b309ec25d`.

Root-only guidance misses instructions for packages encountered later in a run. Eager recursive loading would consume repository-wide context and mix sibling guidance. A strict pre-effect visibility protocol, however, would turn advisory instructions into a second execution gate with batch retry and approval machinery. The operator authorized best-effort delivery instead: new scope instructions inform the *next* model decision, without retroactively controlling an already authorized tool call.

Source authority remains separate from execution placement. A selected source may be local, virtual, or independently stored. A child checkout or inferred host parent cannot replace the admitted source or grant a native execution run read access.

## Proposed decision

The [acceptance plan](../acceptance/agents-instruction-hierarchy.md) records the approved base product choices and this proposed amendment's four selected technical contracts. Human review is still required before #2110 implementation uses the amended baseline. This ADR does not claim implementation or amendment approval.

### Use one admitted composition path

Extend in place the single required `InstructionAssembler.Assemble(ctx context.Context, directories []string, state *session.InstructionSnapshot, maxContentBytes int) ([]session.Message, []InstructionManifest, error)` method. The free `AssembleWithManifest` takes the same arguments and returns the same three values, only nil-safely delegating; no optional manifest/target-aware interface or legacy overload. `DiscoverInstructions(ctx context.Context, source tool.WorkspaceReader, directory string)` returns the same three values for **one** source-relative scope (AGENTS first; CLAUDE on missing/blank only; genuine error never falls back). `RootAssembler` carries `Source tool.WorkspaceReader`, nonempty opaque `SourceID` (logical binding including revision, not host path), and required valid source-relative lexical `SourcePrefix` (`.` for identity). `InstructionManifest` retains `Kind`/`Provenance` and adds `SourceID`, `Directory`, `File` strings and `Partial`, `Omitted`, `HasGuidance` bools. Each message has one row: `Directory` is an execution-relative logical scope, `File` the selected logical source-relative filename. Warning-only rows have no guidance and cannot win whole-source `replace`.

Keep one `Deps.Instructions` path and existing source registration, trust admission, placement, ordering, exclusions, and whole-source `combine`/`replace` policy. The loop normalizes covered `LocalFileOperands` to execution-relative directories using existing lexical helpers (including in-root absolute operands); escaping operands do not discover guidance but ordinary tool semantics do not change. Pass `.` and retained directories. The real binding supplies `SourcePrefix`, not `filepath.Rel` between unrelated roots; root assembly includes explicitly admitted broader-prefix ancestors. Composition handles value/pointer `MultiAssembler`, `RootAssembler` and `RulesAssembler` without dropping unrelated leaves. Global contributors ignore targets/state and keep their existing lifetime; migrate all custom assemblers and wrappers to forward the canonical parameters. No parallel path, new transport/API endpoint, or instruction-specific effective-call deferral.

### Discover lexical scopes inside the selected source

Probe only the selected admitted instruction-source root through the starting folder for the first provider request: no recursive repository/module/sibling scan. The instruction-source root is the root of the selected source, not a repository or Git root. The default source selected at the starting subfolder uses that subfolder as its root. For the proposed contract, `cd repo/website && mecatui` therefore loads from `repo/website` and excludes `repo/AGENTS.md`, even if that ancestor is trusted. <!-- lint:not-a-citation: illustrative repository layout --> An explicitly selected admitted broader source rooted at `repo` is the positive control: it may contribute `repo/AGENTS.md` before `repo/website/AGENTS.md`. <!-- lint:not-a-citation: illustrative repository layout --> This boundary comes from explicit source selection, not automatic ancestor expansion.

Covered structured file tools then reveal new directory chains within the same trusted source/subtree mapping. Probe ancestors only inside the selected admitted instruction source; traversal never admits another source or loads outside that boundary. No recursive scanning, upward host walks, or Git-root inference. Preserve nonconflicting ancestors and give the nearest directory precedence on conflicts. Within *each* directory, prefer nonblank `AGENTS.md`; use `CLAUDE.md` when AGENTS is missing or blank. A genuine read error cannot select CLAUDE as a fallback. Frame sibling scopes independently so one sibling does not govern another; lexical in-root aliases keep lexical applicability, while the source backend confines its reads.

Source precedence is separate from directory precedence. Whole-source `replace` selects on the retained target set, not separately for each target. If source A has only `website/AGENTS.md` and lower-priority source B has root guidance, a retained website-and-services view can select A and omit B entirely. Services gets no B fallback in that view, although a services-only run can select B. The website instructions still apply only to website. Suppressed retained bodies count toward the combined content cap, but absence and warning-only rows (`HasGuidance=false`) cannot select a replacing source. Explain suppression to model and client; a loaded snapshot does not imply emission contrary to current source policy. `combine` keeps operator source order. Target strings can discover scopes, but cannot select a source or mint ReadLedger evidence.

### Deliver guidance on the next request, not as an execution gate

Initial guidance and newly encountered scopes appear as ephemeral project context in provider requests. `engine/session` owns concrete `InstructionScope{SourceID, Directory, File, Text string; Partial, Omitted, Examined, Unavailable bool}` (`Directory` is a source-relative key) and `InstructionSnapshot{Directories []string; Scopes []InstructionScope; DiscoveryExhausted bool}`. Examined absence has empty `Text`, no omission or unavailability; genuine error/unavailability is examined, not automatically retried. `Session` privately owns `instructionSnapshot` via deep-copying `InstructionSnapshot() InstructionSnapshot` and `ReplaceInstructionSnapshot(InstructionSnapshot)` aggregate methods. Mutate at request/dispatch barriers, collecting read-parallel bookkeeping with existing dispatch synchronization. Keep loaded text through messages, approvals and compaction in the same live session; adding scopes never rereads examined text. Explicit Read retains its ordinary behavior. Automatic text and bookkeeping do not persist in conversation, events or stored snapshots.

Live embedded execution keeps the same aggregate. Server `Service` keeps a private attachment keyed by `(SessionID, IncarnationID)` bounded by existing session capacity; hydrate authorized store-loaded aggregates under run ownership/lease and publish on settled/parked boundaries before releasing ownership, for shared-engine and per-session factory alike. The attachment is not tied to engine object lifetime. Evict on successful close/delete, service teardown/ownership loss or incarnation change; restart/owner reattachment begins empty and may rediscover. Revalidate source admission and inherited exclusions before reusing any text; changed binding/policy discards ineligible entries without refresh. Fresh-context children start empty and read current inherited admitted sources; conversation forks deep-copy the parent's snapshot, attenuate exclusions/no-FS before use, then discover independently against their own budgets. Worktree forks inherit known source mapping via existing factory, not by trusting their checkout or inferring a Git root. Implementation updates [ADR 0027](0027-cloud-native.md) Lists 1/2 with owner, lifetime, cleanup and restart state; no new port/store.

New guidance need not have appeared in the request that generated the current batch. Same-batch Read/Edit and first-touch Write, Copy, Move, or Remove may execute before it reaches the model. Do not defer the batch, retry instruction-specific calls, recheck guidance before each effect, or bind approval to instruction visibility fingerprints. Existing permissions, effective-argument authorization after rewriting, read-before-edit, CAS, create-only writes, and read-parallel/mutate-serial dispatch remain authoritative. Instructions are guidance, not a filesystem sandbox or authorization boundary.

Shell, MCP/custom tools, and ListDir/Glob/Grep do not supply structured affected-path discovery. A real factory must give the model a visible limitation and encourage structured tools for concrete scope discovery; do not infer shell effects from command strings. Neither chat mentions nor opaque-only tasks promise nested activation.

### Bound instruction loading without blocking tool execution

Operator-only YAML `harness_context.project_instruction_max_bytes` is `*int permconfig.HarnessContextSection.ProjectInstructionMaxBytes`, resolved into `int app.Config.ProjectInstructionMaxBytes` and `int agent.Deps.ProjectInstructionMaxBytes` for shared/per-session/child/factory paths. Omitted YAML and Go zero default to 65,536 bytes; explicit YAML zero, negatives, fractional/nonintegers and overflow are invalid, and build rejects negative Go values. Positive integers may raise the cap without an artificial maximum or unlimited mode. Update the existing strict decoder/config reference via source generation; project files cannot override the operator policy, and no CLI flag/source selector is added. Effective cap is fixed at build/new-session time and inherited by children; no hot-reload promise.

The cap covers UTF-8 bytes of **all retained automatic guidance text**, including currently suppressed sources, not per-file or cumulative reads, frames or backend allocation. Keep earlier loaded text first; truncate on UTF-8 boundaries or omit excess, label partial/omitted for the model and issue safe advisories. A separate metadata allowance has the **same byte value as the configured content cap**: charge UTF-8 bytes of `SourceID + Directory + File` plus one per examined scope, and UTF-8 bytes plus one per retained target directory. Reserve scope metadata before probing, including worst-case filename length (`AGENTS.md`/`CLAUDE.md`), then account for the actual filename. Reserve retained target directories before recording them. On metadata exhaustion set `DiscoveryExhausted` once, emit one safe omission advisory, and stop new-scope bookkeeping/probes without dropping old guidance or blocking tools. Notices/duplicate suppression use the same finite metadata pool: at most one notice per kind/source, or one global notice when full, never a list of rejected paths.

Only previously unexamined selected-source/lexical-ancestor pairs are eligible for new candidate reads; share ancestors. Each pair uses at most two reads (AGENTS then, if missing/blank, CLAUDE), checking cancellation before each; examined absence/error is cached without automatic retry. Stop reads after content or metadata exhaustion; no recursive scans or repeated request-level reads. This structural per-pair read limit plus byte-accounted metadata replaces the unsubstantiated 128-probe/64-directory prototype and later speculative 4,096/16,384 counts. An arbitrary numeric probe ceiling before real adapter evidence would claim a production latency bound the fixture cannot support; instead a synthetic counted remote-reference test with injected latency asserts calls × fixture latency, **not** production p95/SLO. Existing operand/envelope limits remain, and backend reads can allocate a whole file before truncation.

Use existing source read operations and transport envelope protections. Content truncation after a read is not a backend preallocation bound; this design does not add bounded-read protobuf/native/MicroVM operations or require an external MicroVM release. Read faults, containment problems, and unavailable sources must be reported without silently switching to host storage or executing instruction-specific denial. Ordinary provider context-window handling still applies to the complete request; it is distinct from an instruction discovery ceiling.

Native execution-backed instructions require existing binding and active run access. A missing BindingID or a reattached workspace without a run grant makes that selected source unavailable; warn and continue best-effort authorized work. Enabling and qualifying native source reads through the actual authorization and factory-to-provider path is a separate issue/dependency before claiming native support. It is not a completion gate for this hierarchy and does not authorize a run-authority redesign.

### Preserve trust and explain selection

Retain project trust admission, remembered anchors, and first-encounter probing. AGENTS-only repositories gain no implicit trust grant; headless posture is not project trust. Inject diagnostics and reuse `session.EvHook` with `HookPayload{Phase: "ProjectInstructions", Decision: HookAdvisory}` through the existing wire/client projection, without new protobuf fields. Project only static safe reasons and escaped logical scopes, no bodies, raw backend errors or host paths; forward only these safe child advisories to the parent, never all hook events. Tests must observe the actual receiving client. Existing request manifests account for one row per emitted message and framed bytes; whole-source omission is visible. No new inspection API, durable event, watcher or shared scope cache.

## Alternatives

Root-only discovery does not cover later package work; eager recursive discovery adds unrelated sibling text and repository-scale cost. Model-only advice to read guidance cannot guarantee a first-touch edit is informed, but this best-effort proposal deliberately accepts that gap in exchange for ordinary tool progress. A strict pre-effect retry protocol would require whole-batch deferral, per-effect freshness review, and instruction-specific approval evidence despite guidance having no authorization role.

Parsing Shell commands cannot reliably enumerate paths; blocking opaque calls would change existing authority. New bounded-read transport operations and an external runtime release would add implementation and deployment dependencies without providing access to native sources lacking a binding or run grant. Persisted instruction snapshots would require revocation and child/restart semantics that ephemeral context avoids.

## Consequences

Starting-folder instructions appear on the first request; later scopes are encountered through covered tools and delivered in subsequent requests, subject to structurally bounded new-scope reads/metadata and the configured combined content cap. Retention keeps earlier loaded guidance available across a live session and compaction, but cannot promise completeness after truncation/omission; restart can rediscover changed text. Whole-source replacement can leave a sibling without lower-priority fallback. Structural tests establish selection and delivery, not model obedience.

A tool may mutate its target before its local instructions are delivered. Source reads and external writers are not transactional with file effects. Existing backend reads may materialize a whole file before client-side truncation, and unavailable native sources need separate enablement. After human review of this amendment, implementation updates existing exported engine contracts, API snapshots via `task api:update`, classified `engine/CHANGELOG.md`, generated configuration reference, ADR 0027 Lists 1/2 and owning public/context documentation; frozen predecessor ADRs stay intact.
