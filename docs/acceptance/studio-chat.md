Port the prototype's chat feature onto the Studio bootstrap: the BFF gains the session
inventory and lifecycle routes, the run stream (Server-Sent Events carrying an
application-owned event union that preserves unknown SDK kinds), and the run controls; the web
app gains the chat workspace (sidebar, transcript, composer with images, approvals, steering,
folders, queue, diff and code rendering). Model and reasoning-effort selection needs a
deployment model inventory this layer has no source for, so its control stays hidden until the
settings layer supplies one. The BFF contract is taken
verbatim from the prototype, which was designed against the same published SDK 0.3.0.

## Human decisions

- [x] Model and reasoning-effort selection is deferred, not stubbed. — Decision: the composer and the session controls render the model and effort control only when a deployment model inventory is available, and this layer has no source for one: the inventory comes from `GET /api/v1/settings/runtime`, which the settings plan owns. This layer therefore hides the control rather than shipping it present-and-permanently-disabled, and claims no model-selection capability; the settings layer supplies the inventory and the control appears. Rationale: a visible control that can never work is a false affordance, which a review finding against an earlier draft of this layer caught.
- [x] Scope of the port. — Decision: the whole prototype chat feature, BFF and web, including its browser-local conveniences (chat folders, queued messages, local canvas, local file preview, voice input, browser notifications) because they have no BFF dependency and removing them changes the product the design team validated. Debug sessions (`debugTargetSessionId`, the AI-debug binding of [ADR 0254](../adr/0254-session-debugger-admin-transport.md)) stay in the contract but get no dedicated UI beyond what the prototype had.
- [x] Shared web infrastructure the chat workspace needs. — Decision: the shortcuts provider and registry (`features/shortcuts/shortcut-provider.tsx`, `shortcut-registry.ts`), `lib/model-preferences.ts`, `lib/browser-notifications.ts`, and only the UI primitives the chat workspace actually imports (badge, button, card, dialog, alert-dialog, dropdown-menu, input, textarea, tooltip) land in this layer as shared code — primitives the prototype used solely in later features are copied by the plan that needs them; the shortcuts *reference page* stays a later plan.
- [x] Contract provenance. — Decision: the `/api/v1` chat schemas, paths, and operation ids follow the design prototype so the generated client and the ported behaviour tests keep their shape, with one deliberate divergence recorded in the next decision; the bootstrap's stub `streamEventSchema` in `apps/contracts/src/schemas/events.ts` is replaced by the chat run-stream union (a Cleanup of a stub that shipped one layer earlier and has no consumer).
- [x] Activity replay is bounded and resumable. — Decision: `GET /sessions/{id}/activity` does not replay a session's whole durable history on every request. It carries a resume cursor, bounds a no-cursor replay to `STUDIO_ACTIVITY_REPLAY_MAX` events, tells the client when the history exceeded that bound, and caps concurrent streams per session. Rationale: the design prototype replayed unconditionally `from: "start"`, which lets one authenticated browser tie up the backend for frontend and the daemon with unbounded historical reads and stream bandwidth by reattaching repeatedly to a long-lived chat. The authoritative history already has an owner in `GET /sessions/{id}/transcript`; activity exists to catch up and follow a live run. The published SDK's `AttachOptions.from` accepts `"now"`, `"start"`, or a cursor, and every envelope carries an opaque string cursor, so the bound costs no capability.
- [x] Mutations and the bootstrap's security gates. — Decision: every state-changing chat route sits behind the bootstrap's same-origin + double-submit CSRF check and, when interactive login is active, the `401` session gate; the web app's existing request interceptor supplies the header. SSE routes are `GET` except `startRun` and `retrySession`, which are `POST` streams and therefore also CSRF-gated.

## Interface contract

- **gRPC / protobuf:** None — the BFF drives the daemon exclusively through the published SDK's session, run, activity, and control operations.
- **Exported Go APIs / interfaces:** None — no Go source changes.
- **Tool schemas:** None — Studio adds no model-facing tool.
- **CLI / config:** Two Studio-owned bounds on activity replay, read at startup like the bootstrap's other `STUDIO_*` settings: `STUDIO_ACTIVITY_REPLAY_MAX` (default `2000`; positive integer; the most durable replay events one activity request forwards before it reports truncation — live events are never bounded, so a long-running turn streams in full) and `STUDIO_ACTIVITY_MAX_STREAMS` (default `4`; positive integer; concurrent activity streams allowed per session per replica). No flag, task, or compose setting changes.
- **Events / persistence:** The BFF's SSE union `runStreamEventSchema` is a `type`-discriminated union of `run.started {runId, sessionId}`, `run.event {event}`, `run.truncated {reason: "bound"|"gap", cursor}`, and `run.error {code, message}`, where `event` is `serializedMecatlEventSchema` `{kind, runId, seq, turn, text, unknown, payload?, raw?, usage?}`: an SDK event of a kind the SDK does not model is forwarded with `unknown: true`, its wire kind, and its JSON-safe raw data, never dropped; `bigint` fields (`seq`, usage counters) are serialised as decimal strings; `Uint8Array` payload members as `{data, encoding: "base64"}`. Every SSE frame's `event:` name equals its `type`, and every `run.event` frame carries an SSE `id` field holding the opaque cursor of the durable envelope it projects, so a client resumes exactly after the last frame it received. Routes (all under `/api/v1`): `GET /sessions` (`listSessions` → `{complete, items[]}`), `POST /sessions` (`createSession` `{mode, model?, reasoningEffort, toolAccess, debugTargetSessionId?}` → `201 {id}`), `GET /sessions/{id}` (`getSessionDetail`), `PATCH /sessions/{id}` (`renameSession` `{title}`), `DELETE /sessions/{id}` (→ `204`), `GET /sessions/{id}/transcript`, `POST /sessions/{id}/runs` (`startRun` `{prompt, images[]}` → SSE), `GET /sessions/{id}/activity` (SSE; optional resume cursor from the `Last-Event-ID` request header, or the `resumeFrom` query parameter when a client cannot set that header, the header winning on conflict), `PUT /sessions/{id}/mode`, `POST /sessions/{id}/compaction`, `POST /sessions/{id}/fork` (`{model, reasoningEffort}` → `201 {id}`), `POST /sessions/{id}/clear` (→ `201 {id}`), `POST /sessions/{id}/retry` (SSE), `POST /sessions/{id}/runs/{runId}/cancel`, `POST /sessions/{id}/runs/{runId}/steer` (`{text}`), `POST /sessions/{id}/runs/{runId}/permissions/{askId}` (`{verdict: allow_once|allow_always|deny}`); controls return `204` or `409` `stale_run_control`. Enumerations: `sessionMode = default|plan|acceptEdits`, `toolAccess = all|noFilesystem` (→ the daemon's `no-fs` profile), `reasoningEffort = default|low|medium|high|xhigh|max`. A replay is bounded: one activity request forwards at most `STUDIO_ACTIVITY_REPLAY_MAX` durable replay events and never reads past that bound, while live events stay unbounded so a long turn streams in full. When the durable history exceeds it, the stream ends with one `run.truncated {reason: "bound", cursor}` frame naming the last cursor delivered; the client then reads `GET /sessions/{id}/transcript` for the authoritative history and reattaches from that cursor. A durable gap carries no cursor, so the stream ends with `run.truncated {reason: "gap", cursor: ""}` rather than resuming across a hole. The request that delivers the `STUDIO_ACTIVITY_REPLAY_MAX`-th replay event ends right after it with `run.truncated {reason: "bound"}` naming that event's cursor, and reads no further envelope. A stream resumed from a cursor starts with the next durable event itself — no `run.started` precedes it, because the client already follows that run — and a later run in the same stream still gets its `run.started`; a client that sees a durable event of a run other than the one it follows moves its controls to that run. An unusable cursor is `400` `invalid_cursor`, never a silent full replay; so are the SDK's `start` and `now` sentinels and any cursor over 1,024 characters, from either the header or the query. A daemon `activity_gap` error ends the stream exactly as a gap envelope does. The route commits its SSE headers once the replay reaches the live boundary, so an idle session's stream opens without waiting for a live event, and it writes an SSE comment every 15 seconds so an idle stream survives proxy timeouts. A browser view follows only the run of the session it shows: switching chats detaches the previous stream, and controls, approvals, and queued messages address the session that owns them. On `run.truncated {reason: "bound"}` the view — the main chat and a side thread alike — reattaches from the cursor (at most 50 times per open) until it reaches the live run, without reporting the run as stopped; on `gap` it reloads the transcript and says history is missing. Browser-only persistence in `localStorage` under the `studio.chat.` prefix: `folders`, `queue.{sessionId}`, `canvas.{sessionId}`, `composer.enterToSend`, `models.disabled`; malformed values are treated as empty, never thrown on.
- **Security / authority:** All chat routes inherit the bootstrap gates: `401` without a session when interactive login is active, the same-origin + `X-Studio-CSRF` check on every `POST`/`PUT`/`PATCH`/`DELETE` (the two `POST` SSE streams included), per-request credential binding so one browser's bearer never drives another browser's run. Image attachments are bounded before any SDK call: ≤16 parts, `image/*` MIME only, ≤10 MiB per part and ≤20 MiB aggregate as padded base64, and a prompt must carry text or at least one image; the SDK's own decoded limits remain authoritative. Session titles are trimmed to 1–160 characters; steer text and prompts to 1,000,000. Problem details on chat routes, and every `run.error` message, keep the bootstrap's clamping and bearer/upstream redaction. Padded-base64 validation is a single linear pass, so a payload at the bound is checked without backtracking. Request bodies are bounded before they are parsed: 32 MiB for `POST /sessions/{id}/runs`, 8 MiB for every other `/api/v1` route (a 1,000,000-character text is at most 4 MB of UTF-8), and a larger body is `413` `request_too_large` without being buffered. A persisted image that has only a URL renders as an external link rather than an `img` element, so the page's content security policy keeps images to `'self'`, `data:`, and `blob:` and never loads a remote address. Activity replay is bounded so an authenticated browser cannot make the backend for frontend or the daemon do unbounded historical work: each request forwards at most `STUDIO_ACTIVITY_REPLAY_MAX` replay events, and a session admits at most `STUDIO_ACTIVITY_MAX_STREAMS` concurrent activity streams per replica, beyond which the route answers `429` `too_many_streams` with `Retry-After`. A resume cursor is opaque and is scoped by the daemon to the session it was issued for; the BFF forwards it without interpretation and maps the SDK's refusal to `400`. The BFF never widens what the daemon authorises: delete/rename capability flags and `inspect_only_kind` filtering are the daemon's answers, relayed.
- **Compatibility / migration:** Additive on the BFF (new routes, regenerated OpenAPI and client). The bootstrap's placeholder `streamEventSchema`/`unknownStreamEventSchema` exports are removed with no consumer to migrate. The web nav gains `Chats` as its first item and `/` and `/workspace` redirect to `/workspace/chat`; the bootstrap's `EmptyWorkspace` is removed. The image keeps the bootstrap's `org.stacklok.mecatl.studio.stability=early-access` label: a first usable feature is not a stability promise.

## Deferred decisions and known risks

- Voice input uses the browser's Web Speech API and degrades to a hidden control where unsupported; no BFF involvement.
- The prototype's chat workspace component is large; splitting it is an implementation choice, not a contract.
- Risk: the SDK 0.3.0 event kinds the reducer understands may lag a newer daemon; mitigation is the `unknown` passthrough, which the UI surfaces rather than hides.
- The default replay bound of 2000 events is a starting value, not a measured one: it comfortably covers a long working chat while keeping one request's cost bounded. Operators raise or lower it per deployment.
- Review origin: the bounded-replay decision above answers a blocking review finding against the unbounded `from: "start"` replay this plan first specified.
