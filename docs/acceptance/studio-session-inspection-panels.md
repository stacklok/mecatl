# Mecatl Studio minimap, side panels, and session inspection — acceptance plan

**Contract:** human-reviewed/v2
**Work classification:** Bounded — Studio adds browser presentation and authenticated BFF projections over published SDK operations. [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) owns the browser boundary, and [ADR 0291](../adr/0291-server-owned-session-placement.md) already owns successor placement.
**Decision record:** None — this plan uses existing soul inspection, source-session-scoped worktree selectors, and server-owned placement without changing trust, durable ownership, or daemon authority.
**Phase:** Studio design alignment
**Status:** proposed, 2026-09-25. Reconciled with merged #1847 chat, the #1848 interaction plan, and #1909's authorization review prerequisite. #1848's layered Escape UI and the #1849 activity seam remain pending; the directing human authorized an early stacked implementation.
**Delivery:** Split. The BFF additions and shared panel behavior require an independent interface review. Early stacked implementation remains provisional until this plan merges.
**Expected tasks:** deferred to orchestration
**Issue:** [stacklok/mecatl#1850](https://github.com/stacklok/mecatl/issues/1850).
**Plan PR:** added when opened
**Approved baseline:** absent until this Plan / Interface PR merges

A long chat gains a message minimap that navigates its own transcript. One responsive, resizable panel frame hosts reply threads, local file and tool previews, and a browser-local Markdown canvas. Session inspection shows details, transcripts, the connection's resolved soul, eligible session worktrees, and the existing consent-gated debug action. Inspect-only sessions have a separate read-only entry point.

The merged [chat plan](studio-chat-transcript-composer.md) and [implementation #1886](https://github.com/stacklok/mecatl/pull/1886) supply transcript rows, render-local anchors, preview callbacks, and the existing BFF run union. The merged [#1848 interaction plan](studio-chat-approvals-review-escape.md) owns Escape priority. [Implementation #1909](https://github.com/stacklok/mecatl/pull/1909) supplies authorization review content and exact control prerequisites; its PR explicitly leaves layered Escape and other browser interactions to later #1848 work. [#1849 Plan / Interface PR #1885](https://github.com/stacklok/mecatl/pull/1885) is unmerged and provisional; it owns delegated-activity projection and panel content, currently mounted by [implementation #1907](https://github.com/stacklok/mecatl/pull/1907). #1907 and #1909 both edit `content-preview-panel.tsx`; #1907 also gives activity a local Escape handler. #1850 extracts their shared frame after #1907 settles and keeps their content ownership intact. The frame's close action must yield to the #1848 Escape priority when that browser work lands. The eventual public behavior belongs in `user-docs/building/deployment/studio.md`; this plan does not describe it as shipped.

## Human decisions

- [x] Worktree selection. — Decision: an eligible worktree can be chosen for an explicit Fork or Clear successor through the existing source-session-scoped opaque selector. Selection never rebinds the active session.
- [x] Inspect-only placement. — Decision: show inspect-only sessions in a separate list group. Opening one shows read-only details and, when available, its transcript; no composer or run control appears. Existing debug sessions remain clearly labelled diagnostic chats, with their target read-only.
- [x] Reply identity. — Decision: keep the existing forked-session reply model, but associate a thread with one recorded message occurrence. Equal message text never silently aliases two threads.
- [x] Reply fork point. — Decision: Fork copies the source session's current full history. The selected message is the thread's UI anchor, not a historical branch point; a true branch from that point needs a separate daemon and SDK contract.
- [x] Adjacent ownership. — Decision: the shared frame hosts #1849 activity and #1848 authorization content without parsing their events or redefining Escape order. Stream updates update mounted content without replacing the chosen panel.

## Interface contract

- **gRPC / protobuf:** None — published SDK 0.3.0 already exposes `client.soul.get({$typeName:"mecatl.v1.GetSoulRequest"})`, `client.worktrees.list({$typeName:"mecatl.v1.ListWorktreesRequest", sessionId})`, `Session.snapshot()`, `Session.transcript()`, `client.sessions.fork(sourceId, {worktreeSelector})`, and `Session.clear({worktreeSelector})`. No daemon method, message, field, or number changes.
- **Exported Go APIs / interfaces:** None — Studio's BFF and browser use the published SDK; no Go package changes.
- **Tool schemas:** None — no model-facing tool or argument changes. The existing debug session keeps its read-only `InspectSession` tool.
- **CLI / config:** None — no server flag, environment key, posture, or capability default changes. The existing `studio.chat.contentPanelWidth` account-scoped key retains its 220–420 px clamp and 256 px default.
- **Events / persistence:** Add two read-only BFF operations and extend existing chat projections; daemon events and server persistence stay unchanged.
  - `GET /api/v1/soul` has no session parameter, query, or body. Its 200 `soulInspectionResponseSchema` is `{present:boolean, content:string, sizeBytes:string, sha256:string, provenance:"unspecified"|"user"|"project"|"driver", trusted:boolean, drifted:boolean}`. `sizeBytes` is decimal text; a `present:false` soul has empty content and hash. Map the published SDK `GetSoulResponse.soul` fields, including its provenance enum, without a filesystem read. A missing `soul` message is an invalid upstream response, not an absent soul.
  - `GET /api/v1/sessions/{sessionId}/worktrees` has no query or body. Its 200 `sessionWorktreesResponseSchema` is `{items:Array<{selector:string, kind:string, label:string, branch:string, revision:string, bare:boolean}>}`. Map the published SDK `ListWorktreesResponse.worktrees` for exactly `{sessionId}`.
  - Extend `sessionSummarySchema` with `kind:string` and `sessionActionCapabilitiesSchema` with `publicChat`, `inspect`, `copyId`, `viewTranscript`, and `fork` booleans plus `publicChatReason`, `inspectReason`, `copyIdReason`, `viewTranscriptReason`, and `forkReason` strings from SDK inventory capabilities and reasons. Include owned inspectable rows currently filtered by the BFF; `debugTargetSessionId` distinguishes diagnostic chats from inspect-only rows. Extend `sessionDetailResponseSchema` with `kind:string`, optional `relationship:{debugTargetSessionId?:string, parentSessionId?:string}`, and optional display-only `placement:{kind:string,label:string,branch:string,revision:string}` from `Session.snapshot()`.
  - Extend `forkSessionRequestSchema` with `worktreeSelector?:string` and add an optional `clearSessionRequestSchema` body containing only `worktreeSelector?:string`; a present selector is nonempty and otherwise opaque under the existing request-body limit. An absent or empty Clear body and an omitted Fork selector preserve inherited placement. Regenerate OpenAPI and the browser client from source schemas. The existing `run.started | run.event | run.truncated | run.error` union is unchanged.
  - Keep the canvas at `studio.chat.canvas.{encodedSessionId}` and width at `studio.chat.contentPanelWidth`. Store account-scoped thread maps at `studio.chat.threads.{encodedParentId}` as `{version:2, entries:[{ordinal:number, role:string, digest:string, sessionId:string}]}`. `ordinal` is the zero-based authoritative transcript message index; `digest` is lowercase SHA-256 of UTF-8 `role`, a NUL separator, and final `text`. A thread roots at that row in the UI, while SDK Fork copies the source session's current full history. On read, accept an association only when that ordinal and digest still match. Migrate a legacy content-keyed association only when it matches exactly one recorded row; otherwise keep the older thread available for explicit relinking. Do not persist panel-open state or worktree selectors.
- **Security / authority:** Both new GET routes use Studio's `/api/v1/*` authentication gate, per-request SDK credential context, and `Cache-Control: private, no-store`. `GET /soul` is connection-scoped: it reads the daemon's selected build-time snapshot and accepts no session ID. `GET /sessions/{sessionId}/worktrees` passes that exact ID to SDK discovery, which authorizes ownership and exact source reattachment. A disabled `soul` or `worktrees` runtime capability returns 501 problem details (`soul_unsupported` or `worktrees_unsupported`); an unavailable runtime returns 503. Under interactive authentication, anonymous requests return 401 before SDK access. Unknown and foreign session IDs are indistinguishable 404s. Fork/Clear pass the selector unchanged only for the same source and an explicit successor action; stale, cross-source, cross-owner, and unavailable selectors fail closed under [ADR 0291](../adr/0291-server-owned-session-placement.md), with no default-placement retry. BFF-generated fields, labels, error details, and logs omit credentials, physical roots, cwd, private `EnvironmentRef`, and path inference; arbitrary soul, transcript, preview, and activity content is displayed inertly and is not claimed path-free. Keep the selector only in the open picker, never as visible text, a log field, or stored state. Debug creation retains its evidence-disclosure consent and server authorization.
- **Compatibility / migration:** The BFF additions are additive under API major 1. Existing chat IDs, `/workspace/chat?sessionId`, generated calls, BFF routes, and no-selector Fork/Clear requests keep their behavior. The browser routes `inspect_only_kind` rows to the read-only inspection entry point; a direct link without a proved chat/diagnostic classification does not mount send or run controls. Existing debug sessions remain diagnostic chats, not ordinary inspect-only rows. Legacy thread mappings survive only when one root row matches, and ambiguous mappings stay recoverable through explicit relinking. A reply thread still forks the current full history; the message is a UI anchor. No SDK release is required because [npm SDK 0.3.0](../../apps/server/package.json) already contains the needed operations.

## In scope — 6 scenarios, in implementation order

### Scenario 1 — owned sessions have a truthful inspection entry point

The [Studio chat BFF](../../apps/server/src/mecatl/chat.ts) currently filters inspect-only inventory rows even though the [daemon inventory](../../contracts/proto/mecatl/v1/harness.proto) advertises `inspect` and `view_transcript` separately from `public_chat`. [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) keeps that classification in the BFF before the browser chooses a chat or read-only view.

**Acceptance:**
- AC1.1: the BFF includes owned inspectable sessions with their SDK `kind`, action booleans, and reason codes. The chat list places `inspect_only_kind` rows in a separate inspect-only group; those rows never enter folder, latest-chat, queue, or chat-navigation calculations. A main chat temporarily disabled by `awaiting_approval` or `active_elsewhere` stays a chat with disabled actions. A debug session with `debugTargetSessionId` remains labelled as a diagnostic chat for its own separate session, without implying its target is editable.
  - verify: vitest:apps/server/src/mecatl/chat.test.ts#cHJvamVjdHMgaW5zcGVjdCBvbmx5IHNlc3Npb25zIHdpdGhvdXQgY2hhdCBjb250cm9scw — `chat.test.ts :: "projects inspect only sessions without chat controls"`; inspection — sidebar grouping and latest-chat tests cover mixed kinds.
- AC1.2: opening an inspect-only row or a direct URL for that row shows a read-only details dialog, ID copy when allowed, and a transcript action when `viewTranscript` is true. It never mounts a composer, send, retry, steer, cancel, rename, delete, or fork control for that row. An unclassified direct URL also withholds those controls until the BFF proves a chat or diagnostic classification.
  - verify: vitest:apps/web/src/features/chat/session-inspection.test.tsx#b3BlbnMgaW5zcGVjdCBvbmx5IHNlc3Npb24gd2l0aG91dCBhIGNvbXBvc2Vy — `session-inspection.test.tsx :: "opens inspect only session without a composer"`.
- AC1.3: details show the owned session's safe kind, state, model, usage, and available placement display metadata. A transcript dialog renders the authoritative saved rows in order and labels `complete:false` as incomplete; a disabled or failed transcript read shows a reason without substituting activity replay or creating an editable chat.
  - verify: vitest:apps/web/src/features/chat/session-inspection.test.tsx#Z2F0ZXMgcmVhZCBvbmx5IHRyYW5zY3JpcHQgYW5kIGRldGFpbHMgYnkgY2FwYWJpbGl0eQ — `session-inspection.test.tsx :: "gates read only transcript and details by capability"`.

### Scenario 2 — soul and worktrees use narrow authenticated BFF routes

[ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) keeps SDK calls in the BFF; [ADR 0291](../adr/0291-server-owned-session-placement.md) defines source-scoped selectors. The [SDK namespaces](../../sdk/typescript/src/namespaces-core.ts) and [soul namespace](../../sdk/typescript/src/namespaces-ops.ts) already expose both reads in the published version.

**Acceptance:**
- AC2.1: an authenticated connection-scoped soul read returns only the selected snapshot's content, decimal byte count, hash, presence, provenance, trust, and drift fields. A missing soul is labelled absent; no session selector or filesystem lookup is accepted. Content is inert and is never sent to a model by opening the dialog.

A no-FS source yields an empty list; unavailable discovery reports a disabled state. The dialog has no path entry or inferred workspace root and discards selectors when it closes or the account or source changes.
  - verify: vitest:apps/server/src/routes/inspection.test.ts#bGlzdHMgb25seSB0aGUgb3duZWQgc2Vzc2lvbiB3b3JrdHJlZXM — `inspection.test.ts :: "lists only the owned session worktrees"`.
- AC2.3: choosing one eligible worktree and explicitly confirming Fork or Clear sends its selector only to the existing successor route for that source. BFF-generated route fields, error details, OpenAPI fields, browser labels, logs, and stored state contain no credential, physical placement path, or private environment reference. Arbitrary user-authored inspection content is rendered inertly and is not claimed to be path-free.

### Scenario 3 — a minimap reaches each message in a long chat

[ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) keeps this navigation entirely in the browser.

**Acceptance:**
- AC3.1: each visible user or assistant message has one labelled minimap target. Activating a target scrolls that exact row into the transcript scrollport, including the first few rows of a long history, by clamping the target to the scrollport's own range. It does not scroll the outer page or land at the bottom merely because the target is near the start.

### Scenario 5 — reply threads and local previews remain distinct and safe

The [thread map](../../apps/web/src/features/chat/thread-map.ts) currently keys by role and text hash, while [recorded transcript rows](../../apps/web/src/features/chat/chat-state.ts) have only render-local IDs. The [local preview](../../apps/web/src/features/chat/content-preview-panel.tsx) and [canvas](../../apps/web/src/features/chat/local-canvas.ts) already use browser-local data under [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md).

**Acceptance:**
- AC5.1: replying to two equal-text recorded messages produces two distinct forked sessions and two parent-row associations across stream updates and reload. The selected row is a UI anchor; each Fork copies the source's current full history, including turns after that row. Reopening a row returns to its own thread; the source transcript is unchanged. Before forking, the browser proves the selected row's ordinal and final role/text against the authoritative transcript; an unmatched live or changed row waits for a saved match instead of guessing. A legacy text-keyed mapping migrates only for one unambiguous recorded root; duplicate candidates expose the older thread for explicit relinking rather than attaching it to both.
  - verify: vitest:apps/web/src/features/chat/thread-map.test.ts#a2VlcHMgZXF1YWwgdGV4dCBtZXNzYWdlcyBpbiBkaXN0aW5jdCBmb3JrZWQgdGhyZWFkcw — `thread-map.test.ts :: "keeps equal text messages in distinct forked threads"`.
- AC5.2: file and tool previews retain their source labels, use inert Markdown/code/text rendering, and never fetch a remote image merely to preview it. A local PDF blocked by the shipped frame CSP offers an explicit open/download fallback instead of a blank embed; an unsupported or oversized file explains why no inline preview appears. Previewing does not send the file to Mecatl.
  - verify: vitest:apps/web/src/features/chat/content-preview-panel.test.tsx#cmVuZGVycyBmaWxlIGFuZCB0b29sIHByZXZpZXdzIHNhZmVseSB1bmRlciB0aGUgc2hpcHBlZCBjc3A — `content-preview-panel.test.tsx :: "renders file and tool previews safely under the shipped csp"`.
- AC5.3: the Markdown canvas edits and previews only account-scoped browser data for the selected session. It survives stream updates and same-account reload, resets on account change, and remains usable in memory if browser storage is unavailable; no canvas text enters a BFF request without an explicit normal composer action.
  - verify: vitest:apps/web/src/features/chat/local-canvas.test.ts#a2VlcHMgY2FudmFzIGxvY2FsIGFuZCBhY2NvdW50IHNjb3BlZA — `local-canvas.test.ts :: "keeps canvas local and account scoped"`.

### Scenario 6 — inspection affordances explain unavailable capabilities

The authenticated [runtime schema](../../apps/contracts/src/schemas/runtime.ts) already advertises `soul`, `worktrees`, and `sessionDebug`; the [debugger decision](../adr/0254-session-debugger-admin-transport.md) requires explicit consent before model-visible diagnostic evidence is sent.

**Acceptance:**
- AC6.1: a disabled soul, worktree, transcript, or debug capability leaves its dialog or action visibly unavailable with a reason and makes no disabled SDK call. An open inspection dialog keeps its selected view, focus, and scroll position across ordinary transcript updates. Soul follows the connection, worktrees and transcripts follow the selected owned session, and a session or account switch clears stale inspection content. Debug creation targets only the selected owned ID, shows the existing evidence disclosure before sending, and never changes the inspected target.

## Deferred decisions and known risks

- #1885's activity contract and #1907 implementation are in flight, and #1848's layered Escape browser work remains pending after #1909. The directing human authorized early stacked implementation against this proposed plan; reconcile #1907's final content props and local Escape handling with #1848's central priority and the merged #1909 authorization content before claiming AC4.2 or AC4.3.
