# Mecatl Studio MCP inventory and draft insertion - acceptance plan

**Contract:** human-reviewed/v2
**Work classification:** Bounded — Studio adds a read-only BFF projection and browser draft editing within the existing [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) boundary. The missing daemon and SDK tool-list operation is a separate release prerequisite, not part of this Studio change.
**Decision record:** None — the plan uses the established one-origin BFF, published SDK, and ordinary composer draft; it introduces no new trust, placement, or persistence decision.
**Phase:** Studio design alignment
**Status:** draft, 2026-09-29. The shared panel plan [#1939](https://github.com/stacklok/mecatl/pull/1939) and implementation [#1942](https://github.com/stacklok/mecatl/pull/1942) remain open. Their final merged interface and a published SDK tool-list method must be reconciled before this plan becomes proposed.
**Delivery:** Split. The authenticated BFF contract and cross-view insertion behavior need independent interface review.
**Expected tasks:** deferred to orchestration
**Issue:** [stacklok/mecatl#1851](https://github.com/stacklok/mecatl/issues/1851).
**Approved baseline:** absent until this Plan / Interface PR merges

Studio shows the connection's configured MCP servers, catalog-admitted tools, and advertised prompts and resources. A signed-in reader can browse and search them. On a view with an editable composer, choosing a tool, prompt, or resource inserts a type-labelled reference into its draft at the saved caret or selection. Inspect-only views provide browsing without insertion. Selection does not submit a prompt, expand a prompt, read a resource, or call a tool.

The merged [chat contract](studio-chat-transcript-composer.md) supplies the composer and draft model. [#1850](https://github.com/stacklok/mecatl/issues/1850) owns the reusable panel frame; this issue owns MCP content and the insert menu. The published npm SDK 0.3.0 pinned by [Studio](../../apps/server/package.json) already has `client.mcp.listSources`, `listPrompts`, and `listResources`, but its source response lacks `revision`, `stale`, and `reconciling`. Published 0.4.0 adds those source fields. Inspection of both published versions on 2026-09-29 found no `client.mcp.listTools` or equivalent tool-list method. Studio implementation waits for a subsequent published SDK release containing the separate tool-inventory prerequisite. The eventual browser workflow belongs in [the Studio guide](../../user-docs/building/deployment/studio.md); this plan makes no claim that it has shipped.

## Human decisions

- [x] Server selection. — Decision: a server row opens its tools, prompts, and resources. Only those leaf entries insert references.
- [x] Tool-list ownership. — Decision: the daemon and SDK tool-list addition ships and is published separately before #1851 implementation. This plan stays within Studio's BFF and UI scope.
- [x] Draft representation. — Decision: insert type-labelled, editable plain text using exact MCP identities. Do not add a token parser or hidden attachment.
- [x] View availability. — Decision: the connection-scoped inventory panel is available on signed-in draft, editable-chat, and inspect-only views. The insert menu appears only with an editable composer.
- [x] Panel leaf selection. — Decision: choosing a leaf in the panel inserts into the current draft only when that view has an editable composer. Inspect-only views remain browse-only and expose no insert action.
- [x] Stale source snapshots. — Decision: online stale entries remain insertable with a visible notice because insertion only edits the draft. A disconnected runtime hides inventory and disables insertion until reconnection.
- [x] Credential-bearing resource URIs. — Decision: omit resource entries whose URI is malformed, contains userinfo, query, or fragment, or uses the `data:` scheme. Keep eligible URIs exact; never redact an identifier and then offer the changed value for insertion. The panel explains that some resources can be hidden.

## Interface contract

- **gRPC / protobuf:** None — #1851 changes no daemon method, message, or field. A separate prerequisite must publish a connection-scoped, read-only `ListMcpTools` operation and `client.mcp.listTools({$typeName:"mecatl.v1.ListMcpToolsRequest", server:""})`. Its response must identify each catalog-admitted tool's server, remote name, exact model-facing name, and description; a server filter follows the existing empty-means-all resource and prompt list convention. It must omit tools shadowed by a model-name collision, because raw server and tool name concatenation can collide for distinct pairs. The final released interface is reconciled here before `proposed`.
- **Exported Go APIs / interfaces:** None — the Studio BFF consumes the published TypeScript SDK and adds no Go symbol.
- **Tool schemas:** None — inventory and insertion leave the model-visible tool catalog, schemas, permissions, and dispatch unchanged.
- **CLI / config:** None — no flag, environment key, capability default, shortcut registry entry, or browser storage key is added. The panel uses #1850's account-scoped frame width and the composer uses its current in-memory draft and attachments.
- **Events / persistence:** Add one read-only BFF operation and its source Zod schema in `apps/contracts/src/schemas/mcp-inventory.ts`; export it through `apps/contracts/src/index.ts`, then regenerate `apps/contracts/openapi.json` and the generated browser client. No daemon event, durable record, or browser storage key is added.
  - `GET /api/v1/mcp/inventory` accepts no query or body. Its 200 `mcpInventoryResponseSchema` is `{sourceRevision:string, sourcesStale:boolean, sourcesReconciling:boolean, servers:string[], tools:McpInventoryTool[], prompts:McpInventoryPrompt[], resources:McpInventoryResource[]}`. OpenAPI also declares fixed 400, 401, 500, 501, and 503 `problemDetailsSchema` responses.
  - `sourceRevision` is unsigned decimal text from `ListMcpSourcesResponse.revision` and describes the source snapshot, not an atomic revision for all four lists. `servers` is the sorted, unique union of server names in SDK source candidates and the three item lists; it does not assert connectivity.
  - `McpInventoryTool` is `{server:string,name:string,modelName:string,description:string}`; `modelName` is the exact model-facing tool name from the released tool-list SDK response. `McpInventoryPrompt` is `{server:string,name:string,title:string,description:string,arguments:McpInventoryPromptArgument[]}`, where `McpInventoryPromptArgument` is `{name:string,title:string,description:string,required:boolean}`. `McpInventoryResource` is `{server:string,uri:string,name:string,title:string,description:string,mimeType:string,sizeBytes:string}`; nonnegative SDK resource sizes become unsigned decimal text, and a negative size fails projection.
  - Items sort by server and then model name, prompt name, or resource URI. The BFF calls only `client.mcp.listSources({$typeName:"mecatl.v1.ListMcpSourcesRequest"})`, `listTools({$typeName:"mecatl.v1.ListMcpToolsRequest",server:""})`, `listPrompts({$typeName:"mecatl.v1.ListMcpPromptsRequest",server:""})`, and `listResources({$typeName:"mecatl.v1.ListMcpResourcesRequest",server:""})`. Empty server filters return the connection's union. Duplicate model-facing names in a tool-list response fail projection rather than making either entry insertable. Resource entries with an invalid URI, userinfo, any query or fragment, or a `data:` scheme are omitted; eligible URI identities remain unchanged. It never expands prompts, reads resource content, or executes tools.
- **Security / authority:** Register the GET under Studio's existing `/api/v1/*` session gate and per-request SDK credential context. With interactive auth, anonymous or expired callers receive 401 before SDK access. Require negotiated runtime `connection:"online"` and `capabilities.mcp:true`; otherwise return 503 `runtime_unavailable` or 501 `mcp_inventory_unsupported`, with no inventory SDK call. SDK unimplemented maps to fixed 501 `mcp_inventory_unsupported`; upstream unauthenticated preserves the existing 401 `session_expired` and session clear; other upstream/projection failures map to fixed 500 `mcp_inventory_failed` with a retryable UI state. Install path-specific `Cache-Control: private, no-store` middleware before the session and negotiation gates so even short-circuit responses carry it. Project fields by allowlist: omit source/server transport URLs, diagnostics, headers, structured credentials, tool input schemas, resource contents, and prompt messages. The URI eligibility rule excludes obvious credential-bearing forms; arbitrary remote-supplied names and URI paths cannot be certified secret-free. Render all projected text inertly, never navigate to a resource URI, and send a selected URI to the model only through a later ordinary user send. Opening or selecting an entry grants no run or tool authority. One origin remains the browser-to-BFF path under [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md).
- **Compatibility / migration:** The route is additive under Studio API major 1. Existing chat, queue, steer, image attachments, and draft behavior stay valid. Studio may use only an npm-published SDK version containing the prerequisite tool-list method; pinned 0.3.0 and published 0.4.0 do not satisfy it, and dependency update [#1965](https://github.com/stacklok/mecatl/pull/1965) alone does not unblock #1851. The #1850 panel host and [#1975](https://github.com/stacklok/mecatl/pull/1975) Escape completion remain provisional until merged. Reconcile their final props and Escape ownership before changing this plan to `proposed` or implementing MCP content.

## In scope - 3 scenarios, in implementation order

### Scenario 1 - a signed-in caller receives a safe MCP inventory

The [Studio BFF gate](../../apps/server/src/app.ts) owns authentication and credential forwarding, while the [MCP SDK namespace](../../sdk/typescript/src/namespaces-core.ts) is connection-scoped. The [runtime capability schema](../../apps/contracts/src/schemas/runtime.ts) already carries `mcp` and connection state. [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md) keeps the browser on the BFF's generated route.

**Acceptance:**
- AC1.1: `GET /api/v1/mcp/inventory` returns the exact schema above from the published SDK, including servers with no leaf entries, prompt arguments, decimal resource sizes, and the source snapshot status. Generated OpenAPI and browser calls match the source schema. Transport URLs, structured credentials, diagnostics, schemas, and fetched content are absent from the JSON projection. A duplicated model-facing tool name fails projection rather than presenting a misleading insertable row. Resource URIs with userinfo, query, fragment, `data:` scheme, or invalid syntax are absent; eligible URI values are unchanged.
  - verify: `vitest:apps/server/src/mecatl/mcp-inventory.test.ts#cHJvamVjdHMgYSBzYWZlIGNvbm5lY3Rpb24gc2NvcGVkIE1DUCBpbnZlbnRvcnk` — `mcp-inventory.test.ts :: "projects a safe connection scoped MCP inventory"`; `task studio:generated-check` checks the generated contract.
- AC1.2: the interactive auth gate returns 401 for anonymous and expired callers before touching the SDK. Unsupported `mcp` returns 501 without SDK access; nonempty query or body returns fixed 400 before SDK access, and the route has no session ID. The browser calls only the generated BFF route, never a daemon endpoint.
  - verify: `vitest:apps/server/src/routes/mcp-inventory.test.ts#cmVqZWN0cyBhbm9ueW1vdXMgYW5kIHVuc3VwcG9ydGVkIE1DUCBpbnZlbnRvcnk` — `mcp-inventory.test.ts :: "rejects anonymous and unsupported MCP inventory"`.
- AC1.3: an offline or reconnecting runtime returns a fixed 503; SDK unimplemented returns a fixed 501; upstream unauthenticated clears the session and returns 401 `session_expired`; other SDK or projection errors return a fixed 500. All inventory responses, including pre-route 401 and 503, are private and no-store. Error details and captured logs contain no upstream URL, credential, or raw diagnostic. Reopening after recovery refetches under the current caller's credential.
  - verify: `vitest:apps/server/src/routes/mcp-inventory.test.ts#cmVwb3J0cyBkaXNjb25uZWN0ZWQgYW5kIGZhaWxlZCBNQ1AgaW52ZW50b3J5IHNhZmVseQ` — `mcp-inventory.test.ts :: "reports disconnected and failed MCP inventory safely"`.
- AC1.4: the implementation dependency check inspects the installed npm package's `McpInventory` declaration and generated method, and fails release readiness until the published tool-list operation is present. The BFF has no import from `sdk/typescript` or its generated proto tree.
  - verify: inspection — compare the resolved `apps/pnpm-lock.yaml` SDK version and npm package declaration against the four BFF calls; `task studio:check` validates published-package imports.

### Scenario 3 - choosing a leaf edits the draft at the cursor

The [chat composer](../../apps/web/src/features/chat/chat-composer.tsx) already owns the controlled text draft and image attachments. The merged [chat acceptance plan](studio-chat-transcript-composer.md) retains IME-safe Enter handling, queue, and steer behavior. MCP insertion uses that same composer instance within [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md).

**Acceptance:**
- AC3.1: an Insert from MCP menu is available on new and live editable composers when the runtime is online and `mcp` is supported. It searches and groups the same inventory as the panel. Inspect-only views have no composer or insert menu. A server row browses; selecting a leaf closes the menu without submitting anything.
  - verify: `vitest:apps/web/src/features/chat/mcp-insert-menu.test.tsx#b3BlbnMgdGhlIE1DUCBpbnNlcnQgbWVudSBvbmx5IGZvciBlZGl0YWJsZSBkcmFmdHM` — `mcp-insert-menu.test.tsx :: "opens the MCP insert menu only for editable drafts"`.
- AC3.2: choosing a leaf from the panel or insert menu puts the same reference in the editable composer: a tool inserts `MCP tool: server=${JSON.stringify(server)} name=${JSON.stringify(name)} modelName=${JSON.stringify(modelName)}`, a prompt inserts `MCP prompt: server=${JSON.stringify(server)} name=${JSON.stringify(name)}`, and a resource inserts `MCP resource: server=${JSON.stringify(server)} uri=${JSON.stringify(uri)}`. JSON string escaping keeps untrusted line breaks and quotes inside one reference; tool references retain the exact server and remote name even when namespaced model names resemble one another. Insertion replaces the saved selection or enters at the saved caret, adding a separating space only where adjacent non-whitespace text would join. It puts the caret after the inserted reference and leaves existing text and images intact. It never calls `onSend`, a run or tool route, `getPrompt`, or `readResource`.
  - verify: `vitest:apps/web/src/features/chat/mcp-insert-menu.test.tsx#aW5zZXJ0cyBlYWNoIE1DUCByZWZlcmVuY2UgYXQgdGhlIHNhdmVkIHNlbGVjdGlvbiB3aXRob3V0IHNlbmRpbmc` — `mcp-insert-menu.test.tsx :: "inserts each MCP reference at the saved selection without sending"`; inspection — browser network trace shows no run, tool, prompt-expansion, or resource-read request after selection.
- AC3.3: Tab, search, Arrow keys, Enter/Space, Escape, and touch can operate the menu. Enter during IME composition does not choose an item or send. The first Escape closes the focused menu under #1848's priority, returns focus to its trigger, and leaves the draft unchanged. A touch selection preserves the pre-menu caret on mobile and exposes the inserted text for editing.
  - verify: `vitest:apps/web/src/features/chat/mcp-insert-menu.test.tsx#cHJlc2VydmVzIGNhcmV0IGFuZCBJTUUgYmVoYXZpb3IgZm9yIE1DUCBpbnNlcnRpb24` — `mcp-insert-menu.test.tsx :: "preserves caret and IME behavior for MCP insertion"`; inspection — 320/500 px touch and keyboard browser journey.
- AC3.4: a session or account switch while the menu is open invalidates its saved selection and pending inventory response. It cannot insert into another chat's draft. A disabled or unmounted composer keeps any existing draft and attachments under the normal chat contract.
  - verify: `vitest:apps/web/src/features/chat/mcp-insert-menu.test.tsx#ZG9lcyBub3QgaW5zZXJ0IGludG8gYSBkaWZmZXJlbnQgZHJhZnQ` — `mcp-insert-menu.test.tsx :: "does not insert into a different draft"`.

## Definition of done

1. The separate tool-list operation is available in a published npm SDK version used by `apps/server`; #1850's final panel interface and #1975's Escape ownership have been reconciled against this plan before it becomes `proposed`.
2. The implementation candidate passes focused contract, BFF authorization, panel, composer, and offline browser proofs, plus `task studio:check`, `task site:build`, `task docs`, `task lint`, `task test:race`, and the offline demo. No Go API change in #1851 calls for `task api:update`.
3. `task ac-trace-strict` resolves every named proof when the plan becomes `landed`; the implementation PR updates the owning Studio user guide, links this Plan / Interface PR and its approved commit, and reports interface conformance. `/panel-review` has no ship blocker. Humans merge the implementation PR.

## Deferred decisions and known risks

- #1939 and #1942 are open, so `SidePanelShell` props, content selection, and focus return are provisional. #1975 also edits composer and Escape ownership. Reconcile their final merged interfaces before proposing this plan; material drift needs human review through the development process.
- Published SDK 0.3.0 and 0.4.0 lack tool listing. The separate release must supply the exact connection-scoped read and tool identity needed for this BFF mapping before implementation; #1965 upgrades to 0.4.0 but does not satisfy that dependency.
- The URI eligibility rule conservatively hides benign resource identities with queries or fragments. It cannot detect secrets in arbitrary names or URI paths; those remain untrusted, authenticated inventory text.
