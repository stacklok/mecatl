# Mecatl Studio bootstrap — acceptance plan

**Contract:** human-reviewed/v2
**Work classification:** Architectural — adds a new system boundary (a browser-facing BFF holding user credentials in front of a mecatl deployment), a new released deployment artifact, and a durable dependency decision (Studio consumes only the published SDK).
**Decision record:** [ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md)
**Phase:** capability — bring the Studio web UI into the repository as a skeleton and release its image
**Status:** landed, 2026-09-24. Candidate transition after `task studio:check`, `task docs`, `task ac-trace`, and `task lint:actions` passed on the implementation layer; authoritative only when that PR merges. Decisions recorded from the 2026-09-21 design interview on [#1736](https://github.com/stacklok/mecatl/issues/1736); one advisory devils-advocate pass folded in.
**Delivery:** Split, with an explicit stacking exception. The Plan / Interface PR is the root of a `gh stack` series (plan → bootstrap implementation → feature ports → `user-docs/` page); the directing human instructed that nothing in the stack merges until the whole series is reviewed, so the root's merge remains the approval event but is deferred to the end. `/plan-orchestrate`'s merged-baseline precondition is intentionally waived for the implementation layer, which records the exact plan commit instead.
**Expected tasks:** deferred to orchestration
**Issue:** [stacklok/mecatl#1736](https://github.com/stacklok/mecatl/issues/1736).
**Plan PR:** [stacklok/mecatl#1753](https://github.com/stacklok/mecatl/pull/1753)
**Approved baseline:** absent until the stack root merges

Port the architecture of the Studio design prototype into this repository
as a self-contained `apps/` workspace, without its features: a Hono BFF that connects to a
mecatl runtime, authenticates a browser user against the deployment's OIDC issuer, and serves a
React shell from the same origin, released as `ghcr.io/stacklok/mecatl/studio` by the same
sign/SBOM/attest pipeline as the Slack bot image. The prototype's Vercel entrypoint and preview
OAuth relay are not ported. Each product feature (chat, schedules, knowledge, settings, search,
shortcuts) follows as its own Bounded acceptance plan in the same stack.

## Human decisions

- [x] How `apps/server` consumes the SDK. — Decision: the published `@stacklok-oss/mecatl-sdk` from npm only; no `workspace:` or `file:` link to `sdk/typescript`.
- [x] Where the pnpm workspace root lives. — Decision: self-contained at `apps/` with `apps/web`, `apps/server`, `apps/contracts`; no Node toolchain files at the Go root; root Taskfile includes the Studio Taskfile as `studio:*`.
- [x] Bootstrap scope. — Decision: skeleton only — health and runtime routes, auth service and routes, workspace shell, auth gate, generate pipeline. Features port one PR each.
- [x] Runtime modes. — Decision: keep spawn, mock, and external; the product path and the image target external mode against a `mecak8s` deployment.
- [x] Session model. — Decision: encrypted-cookie stateless sessions; Vercel relay dropped; single callback `STUDIO_PUBLIC_URL/api/v1/auth/callback`; dev keeps the mecatui loopback callback on 127.0.0.1:18473.
- [x] Image shape. — Decision: one image, one origin, multi-stage; builder compiles to `dist`; runtime is `cgr.dev/chainguard/node` pinned by digest running `node dist/index.js`.
- [x] Name. — Decision: Studio. Image `ghcr.io/stacklok/mecatl/studio`, packages `@mecatl-studio/*`, Taskfile namespace `studio:*`.
- [x] Deployment artifact. — Decision: image, `publish-studio` release job, and `apps/docker-compose.yml` only; Helm/Ingress is a follow-up.
- [x] CI coverage. — Decision: a `studio` relevance category and a job running install, lint, typecheck, test, generated-drift check, and a no-push `linux/amd64` image build.
- [x] Process. — Decision: Architectural, split delivery as a `gh stack` series; this plan plus ADR 0351 at the root, implementation next, feature ports after, the `user-docs/` page on top; no layer merges before the series is complete.
- [x] Environment variable naming. — Decision: target settings keep `MECATL_*`; Studio-owned settings use `STUDIO_*`; the Slack bot's `MECATL_GRPC_ADDRESS` is left unchanged.
- [x] Compose daemon source. — Decision: a Studio-owned `apps/docker/mecated.Dockerfile` built from the repository root context.
- [x] Security baseline. — Decision: full hardening in the bootstrap — a `Host` allowlist against DNS rebinding, a loopback-only default bind outside the image, public-URL-derived cookie flags, CSP via security headers, same-origin check plus double-submit CSRF token on mutations, in-process per-client rate limiting on auth routes, login audit logging, and a `secure-code-reviewer` pass on both PRs.
- [x] Documentation and release timing. — Decision: `apps/README.md`, a Studio section in `docs/architecture.md`, an AGENTS.md bullet, and ADR 0351 land with the implementation layer; the release job is live from the first tag with the `org.stacklok.mecatl.studio.stability=early-access` image label, which stays for as long as Studio may change without notice between versions. The `user-docs/` deployment page is the top layer of the same stack, so the AGENTS.md "same PR" rule is met at stack granularity — an explicit, recorded exception to same-PR granularity, not to the rule.
- [x] Classification of feature ports. — Decision: Bounded, one acceptance plan per feature, whose interface contract is its `/api/v1` surface and SSE event union.
- [x] Static-token and no-auth runtimes inside the image. — Decision: with `STUDIO_IMAGE=1`, a runtime that resolves to a static bearer or to no interactive login is a startup error unless `STUDIO_ALLOW_UNAUTHENTICATED=1`; both modes always log a startup WARN and are reported by `/api/v1/auth/session`. Local development sets no `STUDIO_IMAGE` and is unaffected; the compose file runs the image and sets `STUDIO_ALLOW_UNAUTHENTICATED=1` for its no-auth `mecated`.
- [x] Where discovery finds the protected-resource document. — Decision: optional `MECATL_RESOURCE_URL` names the canonical RFC 9728 resource; when unset the resource is `MECATL_BASE_URL` canonicalised (query and fragment stripped, trailing slash removed), exactly as the prototype derives it. A `404` disables interactive login; every other discovery failure is a startup error. No switch disables discovery.

## Interface contract

- **gRPC / protobuf:** None — Studio consumes the published SDK; no message, field, or service under `contracts/proto/` changes.
- **Exported Go APIs / interfaces:** None — no Go source changes; the only Go-adjacent edits are the root `Taskfile.yml` include, the `.github/scripts/relevant-changes.sh` category and its test, and the CI/release workflows.
- **Tool schemas:** None — Studio is a client; it adds no model-facing tool or prompt affordance.
- **CLI / config:** Environment read by `apps/server` at startup; every startup error exits non-zero before listening with a stderr message naming the offending variable. Target: `MECATL_BASE_URL` (http/https authority of the mecatl gRPC listener; selects external mode), `MECATL_RESOURCE_URL` (optional canonical RFC 9728 resource; default derived from `MECATL_BASE_URL`), `MECATL_AUTH_TOKEN` (static bearer; requires `MECATL_BASE_URL`; disables browser login), `MECATL_DEV_MOCK` (`1` only; spawns `mecated --mock`; rejected with `MECATL_BASE_URL`), `MECATED_BIN` (binary path for spawn mode; default `PATH` lookup). Studio: `STUDIO_PUBLIC_URL` (browser-facing origin, e.g. `https://studio.example.com`; required when interactive login is active or `STUDIO_IMAGE=1`), `STUDIO_SESSION_SECRET` (the raw UTF-8 bytes are the secret; ≥32 bytes; required when interactive login is active, otherwise an ephemeral secret is generated with a WARN), `STUDIO_PORT` (default `3100`), `STUDIO_HOST` (listen address; default `127.0.0.1`, or `0.0.0.0` when `STUDIO_IMAGE=1`), `STUDIO_IMAGE` (`1`, set by the Dockerfile `ENV`; refuses spawn and mock modes), `STUDIO_ALLOW_UNAUTHENTICATED` (`1`; required with `STUDIO_IMAGE=1` for static-token or no-auth runtimes), `STUDIO_TRUSTED_PROXY_HOPS` (default `0`; when `>0`, the client address is the corresponding right-most `X-Forwarded-For` entry, otherwise the socket peer), `STUDIO_RATE_LIMIT_MAX` (default `20`) and `STUDIO_RATE_LIMIT_WINDOW_MS` (default `60000`) for `/api/v1/auth/*` except the `GET /api/v1/auth/session` poll, plus the `/oauth/callback` alias, `STUDIO_LOG_LEVEL` (default `info`). Taskfile: `studio:install`, `studio:lint`, `studio:format`, `studio:typecheck`, `studio:test`, `studio:generate`, `studio:generated-check`, `studio:check` (lint + typecheck + test + generated-check), `studio:dev` (spawn mode against `../bin/mecated` via `MECATED_BIN`, BFF on `3100`, Vite on `127.0.0.1:18473` proxying `/api` and `/oauth/callback`), `studio:image` (local `docker build` of the Studio Dockerfile); `task ac-trace`, `ac-trace-strict`, and `ac-trace-matrix` gain `studio:install` as a dependency. Compose: `apps/docker-compose.yml` with services `mecated` (built from `apps/docker/mecated.Dockerfile`, context `..`, `--grpc-addr=0.0.0.0:50051 --http-addr=0.0.0.0:8080`) and `studio` (built from the Studio Dockerfile, context `.`), `MECATL_BASE_URL=http://mecated:50051`, `MECATL_RESOURCE_URL=http://mecated:8080`, `STUDIO_PUBLIC_URL=http://127.0.0.1:3100`, `STUDIO_ALLOW_UNAUTHENTICATED=1`, only the Studio port published, on loopback. CI: `.github/scripts/relevant-changes.sh studio` with the positive allowlist `apps/*|.github/*|Taskfile.yml` and a `studio_relevant` output. Release: `ghcr.io/stacklok/mecatl/studio` tagged with the release tag and `latest` (skipped with a notice when the tag has no `apps/Dockerfile`, or when a dispatch checked out a tag other than the run's own commit, whose build provenance would name the wrong source), labels `org.opencontainers.image.title=studio` and `org.stacklok.mecatl.studio.stability=early-access`.
- **Events / persistence:** No server-side persistence; every replica must hold the same `STUDIO_SESSION_SECRET`. Browser state is four cookies, `Path=/`, `SameSite=Lax`, `Secure` iff `STUDIO_PUBLIC_URL` is `https`: `studio_access` and `studio_refresh` (HttpOnly, 30-day max-age), `studio_login` (HttpOnly, the PKCE transaction, 10-minute max-age), and `studio_csrf` (not HttpOnly, the double-submit token). Sealed values are AES-256-GCM with a random 96-bit IV, the cookie kind as additional authenticated data, and a key that is the SHA-256 digest of the secret bytes, encoded base64url; a sealed value longer than 3800 bytes is `session_too_large`. `index.html` is served `Cache-Control: no-store`; hashed assets are `immutable`. The BFF's `/api/v1` SSE payloads are an application-owned discriminated union that preserves unknown SDK event kinds; the bootstrap defines the union type and the `runtime` snapshot shape in `apps/contracts` without any feature payloads. Generated artifacts `apps/contracts/openapi.json` and `apps/contracts/src/generated/**` are committed and drift-gated.
- **Security / authority:** The browser never holds a mecatl credential; the BFF forwards the user's bearer per request via the SDK credential provider bound to the request's `AsyncLocalStorage` context. Interactive login is Authorization Code + PKCE against the single issuer in the resource's `authorization_servers`; a `404` from discovery disables interactive login and any other failure is a startup error. When interactive login is active, every `/api/v1` request except `/api/v1/auth/*` without a valid `studio_access` session is `401` `unauthenticated`; an access token expiring within 30 s is refreshed single-flight per refresh token before the upstream call, rotation replaces both cookies, and a failed refresh or an upstream unauthenticated error clears all session cookies and returns `401` `session_expired`. `/api/health` is exempt from session gating and rate limiting and is the only `/api` route outside `/api/v1`. `Secure` cookie flags and the callback origin derive from `STUDIO_PUBLIC_URL`, never the request scheme. Every response carries Hono `secureHeaders` with a CSP whose `default-src` is `'self'` and which contains no `'unsafe-eval'`; the BFF emits no `Access-Control-Allow-Origin` header. Every request except `/api/health` must carry a `Host` equal to the host of `STUDIO_PUBLIC_URL`, or, when it is unset, a loopback host (`localhost`, `127.0.0.0/8`, `[::1]`); anything else is `421` `host_not_allowed`, so a page that rebinds its own name to the listener is refused before any route runs. State-changing `/api/v1` requests require an `Origin`, when present, equal to the origin of `STUDIO_PUBLIC_URL` (when unset, `scheme://Host` of the request), `Sec-Fetch-Site: same-origin` when `Origin` is absent, no `Sec-Fetch-Site` other than `same-origin`, and an `X-Studio-CSRF` header equal to the `studio_csrf` cookie; failures are `403` `cross_site_request`. `return_to` is accepted only as an absolute path starting with `/` and not `//`, default `/workspace`. The callback rejects a missing `studio_login` cookie or a `state` mismatch with `400` `login_state_mismatch` and an audit failure record, and leaves any existing session cookies in place. A refresh that succeeded keeps answering requests that still carry the refresh token it replaced for 60 seconds per replica, so a request that left the browser before the rotated cookies arrived reuses the new credential instead of replaying a token a rotating issuer has spent. `GET /api/v1/auth/session` returns `{mode, status, account?}`, where `account`, present only when authenticated, is an opaque stable key derived by hashing the issuer subject, never the subject; the browser clears every `studio.`-prefixed `localStorage` key on sign-out and when a different account signs in, so one person's chat folders, queued prompts, and profile never reach the next. Every `/api/v1` route except `/api/v1/auth/*` and `/api/v1/runtime` waits for compatibility negotiation (up to 10 seconds, inside the request's credential context) before it runs, and answers `503` `runtime_unavailable` if negotiation does not complete, so a feature route never reports a supported capability as unsupported from an empty snapshot. `/api/v1/auth/*` (except the `GET /api/v1/auth/session` poll) and `/oauth/callback` are rate limited per client address (per `STUDIO_TRUSTED_PROXY_HOPS`) in-process, per replica, with `429` and `Retry-After`. Login start, completion, failure, and logout emit structured audit records with event name, issuer subject when known, request id, and client address, never token material. Problem-details `detail` derived from an upstream error is clamped and never carries bearer material or upstream addresses. Static-token and no-auth runtimes WARN at startup, report `mode: "static"` / `"none"`, and inside the image require `STUDIO_ALLOW_UNAUTHENTICATED=1`. The image runs as the Chainguard non-root user and contains no sources, dev dependencies, pnpm, or OS package manager (the pinned Chainguard node runtime ships only busybox `sh` and Node's bundled `npm`).
- **Compatibility / migration:** A new surface; nothing existing changes. The prototype repository remains a design reference and is not archived by this plan. The Slack bot's environment names, Dockerfile, and release job are untouched. The `studio` image carries the early-access stability label; its tag line starts with the repository's next `v*` tag after the stack merges.

## In scope — 5 scenarios, in implementation order

### Scenario 1 — a self-contained `apps/` workspace with a drift-gated contracts pipeline

The workspace mirrors the prototype's three packages under one `apps/` root, following the
repository's existing "one directory owns its Node toolchain" pattern for `sdk/typescript` and
`website/` described in [architecture](../architecture.md) and the module discipline of
[ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md). Generated artifacts are committed and
drift-gated like `contracts/gen` and `engine/api/*.txt` ([AGENTS.md](../../AGENTS.md)).

**Acceptance:**
- AC1.1: `task studio:check` from the repository root runs Biome lint, TypeScript type-checks for all three packages, Vitest, and the generated-artifact drift check, using only `apps/pnpm-lock.yaml` and the pnpm version pinned in `apps/package.json`.
  - verify: inspection — the Studio Taskfile and the root `includes: studio:` entry; exercised by the CI job in Scenario 5.
- AC1.2: `apps/server` depends on `@stacklok-oss/mecatl-sdk` by a published semver range, and no file under `apps/` references `sdk/typescript` by relative path or `workspace:` protocol.
  - verify: inspection — `apps/server/package.json` dependency and a Biome `noRestrictedImports` rule rejecting `../sdk` paths.
- AC1.3: `task studio:generated-check` regenerates `apps/contracts/openapi.json` and `apps/contracts/src/generated/**` from the Hono routes and fails when the committed artifacts differ.
  - verify: inspection — the task runs `pnpm generate` then `git diff --exit-code` over the generated paths; exercised by the CI job in Scenario 5.
- AC1.4: browser code under `apps/web` imports neither `@stacklok-oss/mecatl-sdk` nor any daemon protocol type; it imports only `@mecatl-studio/contracts` and its generated query client.
  - verify: inspection — a Biome `noRestrictedImports` rule for `@stacklok-oss/mecatl-sdk` scoped to `apps/web`.

### Scenario 3 — a browser user signs in through the deployment's OIDC issuer with hardened sessions

The prototype's `AuthenticationService` is ported without the Vercel preview relay and with
the hardening decided for this bootstrap ([ADR 0351](../adr/0351-mecatl-studio-in-repo-web-ui.md),
"Security / authority" above). The mecak8s side of this contract is the protected-resource
discovery described in [architecture](../architecture.md#protected-resource-discovery): the
document is served at the canonical resource's well-known URL, so Studio must be told the
resource when it is not the gRPC authority.

**Acceptance:**
- AC3.1: in external mode without `MECATL_AUTH_TOKEN`, the BFF fetches `<resource origin>/.well-known/oauth-protected-resource<resource path>` for the resource named by `MECATL_RESOURCE_URL`, or derived from `MECATL_BASE_URL` when unset; a `404` disables interactive login and `/api/v1/auth/session` reports `mode: "none"`; a published document yields issuer, public client id, audience, and scopes and must name the same resource.

## Definition of done

1. Applicable `task lint`, `task test`, `task docs`, `task lint:actions`, and `task studio:check` gates pass; `task api:check` is unaffected and stays green.
2. `task ac-trace-strict` resolves every named proof when the plan becomes `landed`.
3. `go run ./cmd/mecademo` remains green (no runtime changes are expected).
4. `apps/README.md` (run, configure, compose), a Studio section in `docs/architecture.md`, and an `apps/` bullet in AGENTS.md land with the implementation layer and pass `task docs`.
5. The implementation PR links the Plan / Interface PR and the exact plan commit and reports interface conformance.
6. `/panel-review` reports no ship blockers or unwaived reviewer failures, and a `secure-code-reviewer` pass over `apps/server` has no unaddressed high-severity finding.

## Deferred decisions and known risks

- The exact Chainguard node digest is chosen at implementation time and recorded in the Dockerfile; only the digest-pinning rule is contractual.
- The CSP directive list beyond `default-src 'self'` and the absence of `'unsafe-eval'` is fitted to the built Vite bundle at implementation time (Tailwind may require `style-src 'unsafe-inline'`, which is acceptable).
- The prototype pins pnpm 12.4.2 and Node 24; Studio keeps those pins since the workspace is self-contained. Aligning with the SDK's pnpm 11 pin is not required.
- The reconnect backoff bounds (AC2.6) are an implementation detail; only "bounded, keeps serving the last snapshot" is contractual.
- Risk: `ghcr.io/stacklok/mecatl/studio:latest` is published from the first tag with no usable features. Mitigation: the early-access stability label, `apps/README.md`, and the user documentation say Studio can change without notice between versions.
- Risk: the published SDK lags a mecak8s change. Mitigation: the runtime route surfaces the SDK compatibility snapshot so the mismatch is visible in the UI banner.
- Risk: the stacking exception defers the approval-by-merge event; the implementation layer records the exact plan commit it built against so drift is detectable at review.
