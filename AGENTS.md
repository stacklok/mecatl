# AGENTS.md — mecatl

> **The canonical coding-agent contract for this repo** (the [AGENTS.md](https://agents.md)
> open standard). `CLAUDE.md` is a **symlink to this file**, so Claude Code and any
> AGENTS.md-aware tool read the same contract. Edit `AGENTS.md`, never the symlink.

A **headless agentic coding harness** in Go 1.26 (hexagonal/DDD): the streaming agent
loop, ~7 tools, permissions, hooks, and subagents behind a provider-agnostic port.
Driven over gRPC + HTTP; an optional Bubble Tea TUI (`mecatui`) is a client.

> `docs/harnesses/` is the **research corpus** this was built from, not
> harness conventions. **Documentation lifecycle (ADR 0002 + ADR 0003):**
> `docs/architecture.md` is the LIVING "how it works" — update it when behaviour
> changes; `docs/usage.md` is how to run it; the *why* of every feature is a **frozen
> ADR** in `docs/adr/` (the former `docs/design/*` records were consolidated there by
> ADR 0003 — each carries a `- Status:` + `- Date:` header, gated by `docs/lint`); a
> shipped/deferred-status tracker lives ONLY in `docs/design/PRODUCTION-READINESS.md`
> and the dense per-subsystem reference in `docs/design/IMPLEMENTATION-NOTES.md`.
> **New** decisions are a new `docs/adr/` entry (copy `docs/adr/template.md`),
> superseded by another ADR, never edited in place.
> `docs/design/IMPLEMENTATION-NOTES.md` is the dense living per-subsystem companion to
> architecture.md. **Prefer adding design detail to those docs, not here** — this file is a
> lean correction file, not documentation.

## Commands

**Always build through the Taskfile** — a bare `go build` in the repo root drops stray
binaries and is the wrong workflow.

```sh
task build              # → bin/mecated, bin/mecademo, bin/mecatui  (NEVER `go build` to repo root)
task test               # full suite, -race (root module + engine module + the GOWORK=off engine-standalone hygiene proof)
task test:golden        # refresh mecatui View/teatest goldens (-update) then re-run
task api:check          # api-compat gate: fail if the engine public surface drifts from engine/api/*.txt (also under task test)
task api:update         # regenerate engine/api/*.txt after an INTENTIONAL core-API change (commit + engine/CHANGELOG.md note)
task e2e                # LIVE e2e vs OpenRouter (real money, needs OPENROUTER_API_KEY exported) — NOT part of task test
task bench              # hot-path testing.B microbenchmarks (-benchmem) for benchstat; BENCHCOUNT=N overrides — NOT part of task test
task perf:scenarios     # OFFLINE whole-loop scenario benchmarks (perf-tracking Phase 2); MECATL_PERF_JSON=path for KPI JSON — NOT part of task test
task pgo:collect        # collect a PROVISIONAL offline CPU profile for PGO into .scratch/pgo/ — NOT committed; see perf-tracking Phase 4
task lint               # golangci-lint v2 + go vet (root module + engine module via --config ../.golangci.yml)
task vuln               # govulncheck reachable-vuln scan over BOTH modules (needs network for vuln DB) — NOT part of task test
task tidy               # tidy BOTH go.mod files: root tidy, go work sync, then engine GOWORK=off tidy
task generate           # regenerate contracts/gen from contracts/proto via buf
cd engine && go test ./agent/ -run TestFullCycle   # a single engine test (engine/ is its OWN module — run go test from engine/, not the repo root)
go run ./cmd/mecademo    # end-to-end demo, fully offline (mock provider)
```

> `engine/` is its **own Go module** (`github.com/stacklok/mecatl/engine`), kept in
> this repo as a MONOREPO via the committed `go.work` (`use ./` + `use ./engine`).
> The root module consumes it via `require …/engine` + `replace …/engine => ./engine`.
> External consumers importing `engine/agent` get only the engine's tiny dep closure
> (`doublestar` + `x/sync` + test-only `goleak`), not mecatl's heavy require cone. A
> `go test ./...` from the repo root does NOT cross the module boundary — engine tests
> are a second invocation from `engine/`. See ADR 0036.

## Architecture (where things live)

Layered DDD; the package's layer is in CAPS. Design rationale lives in `docs/design/`.

Top-level shape: `engine/` is the importable core — the domain packages, the port
interfaces, the agent loop, and the in-tree reference adapters (`engine/adapter/*`) —
fully self-contained (tests included: nothing under `engine/` imports `internal/...`)
and intended to be importable as a library by external consumers; `internal/` holds
the heavy adapters (`internal/adapter/*`) and the composition layer (`internal/app`).
**`engine/` is its OWN Go module** (`github.com/stacklok/mecatl/engine`; ADR 0036),
consumed in-repo via the committed `go.work` and a root `replace …/engine => ./engine`;
its standalone dep closure is just `doublestar` + `x/sync` + test-only `goleak`, so an
external consumer's graph stays small. The repo stays a monorepo — both modules move in
lockstep.

- `engine/session/` — DOMAIN: the `Session` aggregate (state machine), Conversation, the `ToolCall`/`ToolResult`/`Usage` value objects, the `Event` taxonomy.
- `engine/governance/` — DOMAIN: permission `Effect`/`Scope`/`Rule` + `Evaluator`, bash splitting/canonicalization, hook event types. **Session-free** (`session` imports it, never the reverse).
- `engine/tool/` — DOMAIN: `Tool`/`ToolSpec`/`Catalog` **and** the `FileSystem`/`Workspace` interfaces (see gotcha), plus the `SkillSource` port (`skillsource.go`): skills cross it as LOGICAL BUNDLES — identity/metadata (`SkillMeta`), body, payloads by logical name (`SkillAsset`, `ValidSkillAssetName`) — NEVER a path/dir/root (the FS adapter's path business, `FSSource.AssetDir(s)`, is adapter-public NON-PORT API consumed only by composition and the same-package snapshot activator), plus the `AgentDefSource` port (`agentsource.go`): the WHOLE `AgentDef` value object lives here (no locator field; `Origin` is a tier label, never a location; `AgentMCPServer.Headers` is SECRET-SHAPED — never logged/projected), SNAPSHOT semantics — where a def came from is the agents adapter's NON-PORT detail channel (`agents.Discovered.Detail`/`Registry.Detail`). A def's `memory:` head (issue #33, `AgentDef.Memory` = `user`/`project`; READ-ONLY v1, write path deferred) rides the cache-stable `Role`/StablePrefix via `agentPromptConfig` (fenced UNTRUSTED DATA), NEVER per-turn; the **project** tier is `cfg.TrustProject`-gated (same fold as project-tier defs) and the def name is path-sanitized (`safeAgentMemoryDir`) — resolved to a concrete dir ONLY in composition (`resolveAgentMemoryHead`).
- `engine/prompt/` — DOMAIN: two-layer prompt assembly + AGENTS.md/CLAUDE.md discovery; the turn-0 `InstructionAssembler` chain and its consumer-local ports (`MemoryIndexSource`, `SoulSource`, `UserModelSource`, and `CommandSource` + `SourceExpander` — LIVE-semantics slash commands reusing the SAME parse/strip/substitute path as `DirCommandExpander`, so a template expands byte-identically whichever backend serves it; `ValidCommandName` is the ONE invocation-grammar validator). Trust/provenance decisions live in composition, not here.
- `engine/port/` — the PORT interfaces the loop consumes (`LLMProvider`, `SessionStore`, `HookRunner`, `PermissionPolicy`, `Clock`, `Diagnostics`, `ToolCallRecorder`, `EventSink`).
- `engine/agent/` — APPLICATION: the loop (`Engine`/`Run`), dispatch, permission pause/resume, compaction, the Subagent delegation tool, the agent-team `Supervisor`/`TeamTool`. Read-only subagents (Subagent default + read-only team members) run their Bash in an isolated git worktree via a sandboxed runner, TRUST-GATED (issue #40): an untrusted workspace nils the runner — no read-only subagent/member shell, honest Spec note — while Mutating members/Parallel branches keep their HARDENED shells (`buildForceCopyRunner`: force-copy forking runs NO git, so the fork-time checkout RCE the gate closes can't fire there; their run-time git over the verbatim-copied untrusted `.git` is the accepted main-session-parity residual). A `mode:"read-write"` Subagent (ADR 0077, superseding 0040's writable path) is DIRECT-WRITE: no fork, no copy, no merge — it runs Edit/Write/Bash DIRECTLY against the REAL parent workspace (the MAIN session's command runner, main-session parity), exactly as the main agent does, and git is the rollback layer; it stays mutate-serial via the `parentMutatingCaller` seam (now decoupled from any merger) and is NOT isolated (`isolated:false` removes the A2 auto-approve). Default-wired (no flag), per-call default still read-only; a crashed/cancelled child can leave PARTIAL edits (recoverable via git). Scope is the serial Subagent ONLY — Parallel branches and mutating members keep force-copy + serialized merge for genuine concurrency. See `docs/adr/0014-agent-teams.md`, `docs/adr/0077-direct-write-subagent.md`, and the subagent-shell gotcha.
- `engine/adapter/` — the REFERENCE adapters that travel with the importable core (offline tests + sane defaults for any engine consumer): `mockllm`, `memfs`, `memstore`, `sessnap`, `eventsource` (the reference event-log→`*session.Session` fold for event-sourced `SessionStore.Load`, ADR 0038), `permpolicy`, `permstore`, `wallclock` (the production `port.Clock`), `fstools` (the correctness/security-critical FS tool BODIES — Read/Edit/Write/Grep/Glob + the optional Bash — graduated into the importable module per issue #269 so consumers get Edit's read-before-edit/exact-match/uniqueness invariants by import; the root `internal/adapter/tools` re-exports them via alias and adds the host-coupled WebFetch/WebSearch/FetchMcpResource), `fsconformance`, `memconformance`, `storeconformance`, `sourceconformance` (SkillSource/SoulSource/AgentDefSource/CommandSource suites + the canonical fixtures `Fixture`/`AgentFixture`/`CommandFixture` and their `New*FixtureSource` references). Stdlib + engine-only (memfs adds doublestar); strict depguard allowlists; core PRODUCTION code still must not import them (test files may).
- `internal/adapter/` — ADAPTERS: `openai`, `anthropic` (native Messages API), `llmresilience` (retry/breaker + stream-idle watchdog wrapper), `osfs`, `permconfig`, `workspacetrust`, `soul`, `memory`, `skills`, `agents`, `providercatalog` (embedded models.dev subset), `openrouter`, `gitenv`, `hashutil`, `xdgconfig`, `hookexec`, `slogdiag` (the only slog bridge), `store/jsonlstore`, `redisstore` (Redis-backed SessionStore + EventLog + PrunableStore + ToolCallRecorder, ADR 0048; a transport alternative to jsonlstore, validated by the same conformance suites over miniredis), `grpcdriver` (remote session/memory store + skill/soul/agent-def/command source driver clients + server wrappers), `tools`, `server`, and more — see the directory.
- `internal/app/` — COMPOSITION (not domain): the single shared assembly (`app.Build`) of provider registry + catalog + policy + engine into a `server.Service`. The ONLY package allowed to import adapters + `engine/agent`. Per-session provider/model routing, live model listing, capability intersection, trust/soul selection all live here. See `docs/adr/0016-multi-provider.md`.
- `contracts/proto/mecatl/v1/` — gRPC contract (source of truth); `contracts/proto/mecatl/driver/v1/` — the driver protocol (SessionStoreService/MemoryStoreService stores; SkillSourceService/SoulSourceService/AgentSourceService/CommandSourceService content sources) a remote driver process implements; `contracts/gen/` is generated, **never hand-edit**.
- `cmd/mecated/` — standalone server (composition root): flags, TLS/auth/rate-limit, HTTP + metrics listeners. `cmd/mecademo/` — the offline demo. `cmd/mecatequi/` — single-shot HEADLESS composition root (peer of mecademo over `app.Build`): one prompt → a git-diff patch + a JSON Summary + an optional JSONL log + an exit code. It is **FORGE-AGNOSTIC** — knows nothing about GitHub; the glue that turns an issue into a PR lives ONLY in `.github/` + shell, NEVER the binary or `engine/`, and keeps a **split-privilege token boundary** (the agent job holds NO GitHub write token; the publish job runs NO agent code, applies the patch as DATA). See `docs/adr/0028-mecatequi.md`. `cmd/mecak8s/` — storage-free k8s-native agent (ADR 0048), a thin peer of mecated that composes `app.Build` with k8s-native defaults (Redis store + k8s lease + drain gate); no PVC, no local state — state is a managed service (Redis + k8s API server). The four real-provider mains share credential/base-URL wiring via `internal/cliconfig`.
- `cmd/mecatui/` — optional gRPC **client** TUI; by default hosts a `mecated` in-process over a UNIX socket. `ui`/`theme`/`client` import no `engine/...` or `internal/...` and no proto directly — they render from relayed proto `Event`s. See `docs/tui.md`.
- `perf/` — the OFFLINE scenario perf harness (perf-tracking Phase 2, `task perf:scenarios`, NOT part of `task test`): `perf/kpi` (stdlib-ONLY KPI capture — `ScenarioResult`/`Capture`/`/proc` RSS sampler; never imports `engine/...` or `internal/...`) + `perf/scenarios` (external-test `testing.B` whole-loop benchmarks over `engine/...` + `engine/adapter/*`, never `internal/...`). The TUI scrollback render bench lives in `cmd/mecatui/ui/scrollback_bench_test.go` (perf/kpi imported in the `_test` file only). `perf/cmd/perfconvert` (Phase 3; stdlib + `perf/kpi` only) reshapes the scenario JSON into the two github-action-benchmark suites the CI gate consumes, and `perf/cmd/allocsgate` (stdlib only, tested, FAIL-CLOSED) is the deterministic allocs/op gate over `task bench` — the gate DECISION (benchstat is the local human A/B tool only, never the CI gate); the gate is `.github/workflows/perf.yml` (split: allocsgate over `task bench` + github-action-benchmark over the scenarios; PR fails-but-never-pushes, main pushes the `gh-pages` trend store). See `docs/adr/0019-perf-tracking.md`.

## The layering rule (the thing to get right)

Dependencies point **inward only**, machine-enforced THREE ways (all run under `task lint`/`task test`): the **depguard allowlist** in `.golangci.yml` (per-file — each core tier is `list-mode: strict` allowing only `$gostd` + the exact core packages it imports, with an `os` deny on top; a NEW heavy-adapter import is rejected by default; the engine module shares THIS config via `--config ../.golangci.yml`, no engine-local copy); the **DAG test** in `engine/arch/layering_test.go` (whole-graph — transitive direction + cycle detection, which the per-file depguard cannot express); AND the **module boundary itself** (ADR 0036) — the engine is its own Go module, so a stray engine→host-repo import breaks the `GOWORK=off` standalone build outright (`task test:engine-standalone`). `engine/team` is part of the core (agent imports it).

- Domain (`session`, `prompt`, `governance`, `tool`), `engine/team`, and `engine/agent` must **never** import an adapter, `contracts/gen`, `os`, the OpenAI/Anthropic SDKs, or gRPC.
- `engine/port` imports only domain + stdlib. `engine/agent` imports only domain + `port` + `team` (+ stdlib + `golang.org/x/sync/errgroup`) — adapters are injected. (Core **test** files may import the `engine/adapter/*` reference adapters — `memfs`/`mockllm`/`permpolicy`/… — to run offline; the depguard core rules exclude `$test`, and the DAG test reads non-test imports only. The engine tree is fully self-contained, tests included: nothing under `engine/` imports `internal/...` — integration tests that need a heavy adapter live next to that adapter under `internal/adapter/`.)
- Concrete adapters meet ports **only** in the composition layer — `internal/app` and the `cmd/` mains. No DI framework; explicit constructors. Keep wiring in `internal/app`, not in domain/`port`/`agent`.

## Things That Will Bite You

- **`FileSystem`/`Workspace` live in `engine/tool`, NOT `engine/port`.** Moving them to `port` creates a `port↔tool` cycle (`port.LLMRequest` references `tool.ToolSpec`; `Tool.Execute` takes a `Workspace`). Leave them in `tool`. The osfs Workspace also carries READ-ONLY allowed roots (`osfs.WithReadRoots`, fed from `catalogAssets.skillReadRoots`, which the skills seam derives from the skill source ADAPTER — the FS source's per-skill dirs (`FSSource.AssetDirs`) or the remote driver's materialized asset cache) so Read/Stat — never Write/Glob/Grep — serve an activated skill's out-of-workspace files by absolute path; don't strip the option from the workspace factory/fork constructors or out-of-workspace skills regress to unreadable.
- **Every agent-facing shell runs with a SECRET-scrubbed env (security "Finding B") — don't reintroduce the `os.Environ()` passthrough.** The main + sandboxed/force-copy command runners + fork-time git get `internal/adapter/envscrub.Scrub(os.Environ())` (the hardened ones as `gitenv.Scrub(envscrub.Scrub(...))`) via `osfs.WithCommandEnvList`, so under posture `auto`/`yolo` the model can't `echo $OPENROUTER_API_KEY` / `cat /proc/self/environ`. `envscrub` is a stdlib leaf with a precise DENYLIST (the exact harness creds — provider/websearch/`MECATL_*`/`GH_TOKEN` — plus secret-shaped `*_API_KEY`/`*_TOKEN`/`*_SECRET`/`*_PASSWORD`/`AWS_*`/`AZURE_*`), NOT an allowlist (the toolchain `PATH`/`HOME`/`GOPATH`/… must survive). ONE policy across all runners; oracle (mutation-tested) is `internal/app/command_runner_secret_scrub_test.go`. `gitenv.Scrub` only ever did GIT_*/PAGER — it is NOT a secret scrub.
- **`port.PermissionPolicy` is implemented in `engine/adapter/permpolicy`, not `governance`** — `governance` can't import `session` (cycle), so the session-aware policy is an adapter over the session-free `governance.Evaluator`.
- **Preserve these invariants — they have tests that fail if you regress them:**
  - Edit's three invariants: read-before-edit (+ unchanged-since), exact match, uniqueness-unless-`replace_all`.
  - Dispatch is **read-parallel / mutate-serial** (`tool.ReadOnly()` drives it). Two mutating tools must never run concurrently. CARVE-OUT (ADR 0040 seam, ADR 0077): a tool that is `ReadOnly()==true` for fan-out but whose SPECIFIC call will mutate the parent declares the unexported `parentMutatingCaller` (`MutatesParent(call) bool`); the dispatcher excludes that call from the concurrent read batch and runs it ALONE (mutate-serial). A `mode:"read-write"` Subagent (direct-write, ADR 0077) mutates the real tree DURING its run — `MutatesParent` true keeps it dispatch-serial so its in-place Edit/Write/Bash never overlaps a sibling read (it is now decoupled from any merger). A single-branch auto-merging Parallel uses the same seam so its merge-back never overlaps a sibling read; cross-run Parallel merges are additionally serialized by the process-wide `forker.SerializingMerger` mutex.
  - Permissions resolve **deny-dominant**: a deny in ANY scope is absolute. Among ask/allow the higher *configured* scope wins, with ONE narrow exception: a higher-scope config Allow may loosen **only** the built-in-default Ask (the `ScopeBuiltinDefault` floor) — it must NEVER suppress a *configured* Ask. Equal-scope ask/allow ties favor Ask. Plan mode hard-denies mutations first. The six memory tools + the synthetic `soul:apply` action + the three read-only child-observability tools (`InspectSubagent`/`InspectMember`/`SubagentStatus`, issue #37) are floor-scoped (`ScopeBuiltinDefault`) Allows — pre-approved but config-overridable; they loosen no other tool's Ask. (Scope order high→low: `Managed > CLI > LocalProject > SharedProject > User > ScopeBuiltinDefault`.)
  - The bash gate must stay substitution/newline-aware (`$()`, backticks, subshells, `\n` fail safe). Don't simplify `SplitCommands`/`ReadOnlyBash` to operator-only splitting.
- **Subagent Bash permission asks resolve in a 4-step model — do NOT collapse it to a blanket auto-deny.** (1) **A1 read-only substitution** (`governance.SubstitutionReadOnly`) resolves a fully-read-only substitution by the ordinary fold instead of flooring at Ask — GLOBAL (main + children). (2) **A2 isolation auto-approve** (`governance.IsolationApprovable`): an ISOLATED child auto-approves read-only ∪ `{go test,build,vet,list}`, minus the worktree-escape rejections; fail-safe false on any ambiguity. (3) **Surface to human** when the parent is interactive (`Deps.Interactive` installs `Run.childAsks`); clamped/redacted ask, raw args never forwarded (gauntlet #7). (3b) **OPTIONAL headless ask reviewer (issue #31)** — between surface and auto-deny, HEADLESS-only (it fires only when no router was installed, i.e. `!Deps.Interactive`; an interactive deployment surfaces every unresolved ask, so the reviewer is INERT there — mecated must run `--headless` for it to engage, and `normalizeAskReviewerModel` WARNs if it's configured interactive), gated `!ask.ConfiguredAsk` (a configured Ask demands a human, never an LLM reviewer): `Deps.ChildAskReviewer` (`agent.NewEngineAskReviewer` over a tool-less ONE-turn composition-built engine with the no-progress nudge DISABLED — one provider call max, role "ask-reviewer"; wired via `--subagent-ask-reviewer`, empty = off, deliberately NOT a permconfig key — it grants an autonomous approval capability, an operator deployment decision) reviews the ask via `Review(ctx, ChildAskReviewRequest)` — the command rides INSIDE the `untrustedFence` after `neutraliseFraming` (claims of prior approval inside it are void; the prompt's own `Policy:`/`Tool:`/`Requested command:` headers are in the `framingHeader` strip list too). The verdict parse requires the WHOLE output to BE a single JSON object (or a lone ```json fence) — a forged verdict-shaped object echoed inside the fenced command can't be lifted out. Reviewed allow → `VerdictAllowOnce` (never AllowAlways — nothing learned); reviewed deny → `childReviewedDenyMessage` (reviewer named, rationale clamped); `ErrNotReviewable` → ABSTAIN (fall through, breaker UNtouched); any other error/timeout/ambiguity → NOT a verdict, falls through to (4) with the EXISTING message (fail-safe — the reviewer is never load-bearing for safety; all non-abstain errors count toward the breaker). Per-RUN breaker (`Deps.ChildAskReviewMaxDenies`, default 3): consecutive non-allow outcomes open it (reviewer skipped); an allow resets; its mutex SERIALIZES reviews within a run. The allow-INFO, deny-INFO (`decision`/`verdict_reason` + clamped `command`), the one-time breaker-opened INFO, and the reviewer-failure INFO all ride the EXISTING child-ask diagnostic chokepoint in `resolveChildAsk` — NOT a fourth loop line. Child engines force the reviewer nil (no nesting; the reviewer engine itself builds through the child deps path — recursion guard). The gRPC `RunTeam` direct path stays zero-caps (no reviewer). (4) **Headless** → auto-deny with the ACCURATE message (`childAutoDenyMessage`, never "denied by user") + a correlated operator diagnostic. INVARIANTS: `SubstitutionReadOnly`/`ReadOnlyBash`/`IsolationApprovable` + their fuzzers stay byte-for-byte unchanged (a new classifier is a new sibling, fuzzed for positive soundness — `FuzzFlooredConfiguredAllow` is the issue-#32 one); the worktree-escape REJECTIONS live in ONE shared path (`escapeRejectionsFree`) consumed by A2 and the floored-allow bound — never duplicated. **The CONFIG axis (issue #32):** rules carry a `governance.Audience` (zero = all; Main; Subagent) and evaluators a `WithAudience` pin (main policy + soul gate `AudienceMain`; child policies `AudienceSubagent` over `permpolicy.AllowAllFloorRules()` — the child allow-all floor is `ScopeBuiltinDefault`-scoped so it NEVER registers as a configured Allow); permconfig tags top-level deny `AudienceAll` (binds children, tighten-only), top-level allow/ask `AudienceMain`, the `subagent:` block `AudienceSubagent` (trust-gated allows; strict unknown-key parse inside `permissions:` only, skip-WARN names the lost per-effect rule counts). Child-scoped rules land in the child's own deny-dominant fold; children resolve project rules via `pinnedResolver` over the SESSION's pre-fork base root (per-session engines re-pin in `sessionEngineFactory`; never fork roots; the ONE resolver is `cfg.permResolver`, built once in `Build`). On the ask, two mutually-exclusive `PermissionDecision`/`PendingAsk` bits (a third provenance ⇒ extract an AskOrigin enum, not a bool): `ConfiguredAsk` (configured rule won the Ask — SKIPS A2, configured-Ask-never-suppressed; rule-oriented headless deny message) and `FlooredConfiguredAllow` (resolves the floored ask AllowOnce WITHOUT surfacing — bound by `flooredAllowSafe`: **the configured Allow vouches ONLY for the OUTER literal; every recursively-extracted INNER must independently classify positively read-only** (the A1 inner contract — `go test $(git rev-parse HEAD)` clears, `go test $(zap)` surfaces), plus the escape rejections on the blanked outer as defense-in-depth). **Posture ladder (composition, `internal/app/posture.go`): `strict < trusted < auto < yolo`** subsumes `--yolo`/`--trust-project` (now ALIASES) into one tier (`--posture`; operator-global `settings.yaml` `posture:` is OPERATOR-TIER-only — a project file's `posture:` is IGNORED with a WARN, the fail-closed core; `resolvePosture` folds MAX-tier; `applyPosture` runs BEFORE `resolveTrust` and derives the knobs). The `AllowAllTools` rule binds children: `childRules` injects a `ScopeCLI`/`AudienceSubagent` allow-all under `AllowAllTools` (`auto`+`yolo`; mirroring `mainRules` via the shared `yoloAllowAllRule`). The substitution-floor LOOSENING (`WithLooseSubstitution`) is main-only EXCEPT under **posture `yolo`**, where `childEvaluatorOptions(cfg)` ALSO loosens children (`Config.LooseChildSubstitution`) — a child's `$(...)`/backtick/heredoc then AUTO-RUNS (child prompt-injection defense OFF). At `auto`/`trusted`/`strict` it omits the option, so a child's substitution still resolves through the child-ask model (`flooredAllowSafe`: inner must be read-only). Deny-dominance + the configured-Ask floor hold at EVERY tier incl. `yolo`. Pinned by `TestChildSubstitutionLooseningIsTierDependent` + `TestAllowAllToolsBindsMainAndChildren` + `TestPostureResolutionTable` + the headless/interactive yolo e2e in `engine/agent/yolo_child_substitution_e2e_test.go`. Landing narrative + full mechanics: `docs/design/IMPLEMENTATION-NOTES.md` ("4-step model" + "CONFIG axis" sections). Resolution lives in `governance` (classifiers + bits) + `agent` (`resolveChildAsk`/`childPosture`) + composition (audience wiring); no adapter/proto/server type crosses into `agent`.
- **No stdio MCP, ever.** Future MCP is **streaming-HTTP transport only**. Never spawn `os/exec` MCP servers. (mecatl itself never speaks stdio; ToolHive stdio backends are HTTP-proxied and fine.)
- **ACP prompt content is multimodal + capability-gated.** Every block becomes text, a `session.Content` Part, or a loud `codeInvalidParams` — never silent-drop. Reuses `session.NewContent`/`ValidateMediaParts` (no second validation path); image/audio gated on `Service.ProviderCapabilities()`. Audio is wired but dormant (OpenAI Responses has no audio input).
- **Capability truth is a SINGLE composition-computed intersection.** `internal/app/capability.go`'s `modelCapability` = (per-model modalities) ∩ (adapter `Capabilities()`). The modality input is **LIVE-FIRST** (`reg.meta.modalitiesFor` — the SAME live `InputModalities` the picker's `projectModelEntry` reads) with a catalog floor then adapter-only passthrough, NOT catalog-only — don't "simplify" the live read away or the session echo and picker diverge (an OpenRouter text-only model on the shared openai adapter would falsely report `image:true`). The one neutral value feeds ListModels, the `CreateSessionResponse` echo, and the ACP gate — don't recompute it per sink or they'll disagree. Details: `docs/adr/0016-multi-provider.md`.

Both relays (gRPC `Converse` + HTTP SSE) are drain-to-discard after the FIRST Send/Write error: record the error, `run.Cancel()`, keep ranging `run.Events()` discarding until close (no further writes, no `EvPermissionAsk` Persist on the error path), then (gRPC only — the SSE handler returns nothing) return the recorded error — never stop draining on a send error or a busy run wedges in its own emits after the client dies. A run-end-cancelled background child persists and is resumable. Pre-start failures REMOVE the registry entry (never a done+StopNone phantom; a failed RESUME attempt reinstates the displaced prior terminal + its undelivered result); a cancel-while-queued keeps a meaningful StopCancelled entry; a never-driven team member is removed at cleanupAll. **Completion delivery is notice + nudge, both EVENT-SILENT ordinary recorded history (A2/A9/D10):** every turn boundary (drive Step 2a, BEFORE `preTurnTerminal`) announces newly-finished background children in ONE harness-note user message — ids + stop labels ONLY, nothing child-authored; the registry `noticed` flag is SEPARATE from `delivered` (never re-noticed, still collectible; an already-collected result is noticed silently, not listed) and `e.save` runs right after the record (replay-durable). A would-be CLEAN end (meaningful text, benign stop) with LIVE background children is deferred ONCE per run by the background-pending nudge (`finishTurnNoTools`, ids only) — it MUST stay before the clean-terminal calls (`drainChildren` at their top has already cancelled+sealed), never fires on the no-progress/empty-turn path or any non-clean terminal, never relabels the eventual stop, and emits NO `EvNoProgress`; the second clean end terminates normally and the drain cancels+persists what is left.

- **Subagent per-call `model` override re-derives via the engine FACTORY, never clone-and-swap.** `subagentArgs.Model` mints the override child through `WithSubagentEngineFactory` (a composition closure `func(model string)(*Engine,bool)` built by `buildSubagentEngineFactory` over `newChildEngineForProvider`), so Compactor/TokenCounter/`Env.Model`/ContextWindow are RE-DERIVED for the override model — the same "Provider is FIXED per session" discipline. `agent` + `model` together is SUPPORTED via `WithAgentModelEngineFactory` (`buildAgentModelEngineFactory`): the override REBUILDS the named specialist's SCOPED engine (catalog/prompt/skills/hooks/memory, via the shared `buildAgentDefEngine` step) on the override model — NOT the generic explorer set; the override runs on the def's resolved provider, the model taken verbatim (no alias resolution, parity with the model-only path); the pre-built `agentEngines` map is never mutated (fresh engine per call); per-def limits still bind. A def with INLINE MCP servers is declined on the agent+model path (v1 scope limit — the inline manager's live session has no process-lifetime owner on a per-call engine); reference-only MCP is supported (borrows `mainMgr`). `read-write`+`agent` is SUPPORTED via `WithAgentWritableEngineFactory` (`buildAgentWritableEngineFactory`: the specialist's scoped engine rebuilt `allowMutating=true` on the def's resolved provider/model, MAIN runner, direct-write parity — ADR 0058; inline-MCP defs decline, reference-only supported); `read-write`+`agent`+`model` stays REJECTED (v1 scope limit — a writable specialist runs on its own resolved model). Reasoning-effort stays an adapter Option (the factory owns adapter construction), never a `subagentArgs`/`LLMRequest` field. Per-call `subagentArgs.MaxTokens` rides `RunOptions.MaxRunTokensOverride` on `Engine.RunContentWith` (a Run-scoped TIGHTEN-ONLY budget over the SHARED child engine — `effectiveMaxRunTokens` takes the lower non-zero of override and `Deps.MaxRunTokens`); `RunContent`/`Run` delegate to `RunContentWith` with a zero `RunOptions` (legacy run). None widen `port.LLMRequest`.

- **Subagent `fork: true` seeds the child from a DEEP COPY of the parent conversation (issue #34), TRUST-NEUTRAL, SAME-PROVIDER only.** The dispatcher binds `parentCaps.forkHistory` (in `Engine.parentCaps`, over the parent `*session.Session`) returning `session.ForkSnapshot(&sess.Conversation)` — a `CloneMessages` (fresh backing array; `Message` is immutable so the shallow per-element copy is sound — child only appends) with the TRAILING UNANSWERED tool calls stripped (the fork-call orphan, whose result is recorded AFTER dispatch, would otherwise dangle → provider 400). The fresh child is primed via the idle-only `session.Session.SeedHistory` (StateIdle sibling of running-only `ReplaceHistory`; both re-validate `ValidateToolPairing` — double-defended with `ForkSnapshot`'s strip). Copied history is carried VERBATIM, not re-fenced — NOT because the content was "vetted" (the main loop records tool results RAW/UNFENCED via `RecordToolResults`; fencing exists only at team/adjudicator render boundaries), but because the fork is TRUST-NEUTRAL: the child inherits the parent's EXACT raw message posture (whatever fencing the parent applied travels WITH the copied content), runs in a strictly-LESS-privileged read-only explorer sandbox, and introduces NO new untrusted ingress — and re-fencing would bust the byte-stable prompt-cache prefix the feature relies on. It rides `LLMRequest.Messages`; the explorer prompt rides `LLMRequest.System` (no collision). Reasoning/ProviderPhase replay verbatim — safe because `validateFork` REJECTS `fork`+`model` (also `+agent`/`+resume`, first-conflict-wins; then `forkHistory==nil` → "not supported on this run" for plain `Execute`). Snapshot taken SYNCHRONOUSLY in `run()` on the dispatch goroutine (parent keeps appending after a background detach), so the SNAPSHOT SLICE — not the closure — threads into `backgroundChild`/`buildChildSession`. Turn-0 parent → empty snapshot, fork degrades to fresh-context child (benign). No-nesting holds (child catalog has no Subagent). Domain-only, no `port.LLMRequest`/proto change.

- **Subagent structured output is bounded validation-retry, NOT `tool_choice` forcing; the agentId is in the RESULT TEXT.** `subagentArgs.OutputSchema` gives the child a synthetic `SubmitResult` tool (injected run-scoped via `RunOptions.ExtraTools`, never registered into the shared catalog) whose params ARE the schema; the child is PROMPTED to call it (no `tool_choice` — incompatible with Anthropic thinking + the OpenAI reasoning path). `SubmitResult.Execute` validates via `session.ValidateJSON` (a JSON-schema SUBSET validator, FAIL-OPEN on unsupported keywords — the SINGLE structured-output choke point, DISTINCT from `ValidateMediaParts`); on a miss the Subagent tool re-injects a correction and re-drives the SAME child (`session.Reopen`) up to `defaultStructuredOutputRetries` (2), then ends with the new `session.StopStructuredOutput` CLEAN terminal rendered as a MODEL-VISIBLE validation-error tool result (never only a log line). The retry lives in `driveChild`, NOT in the hot shared `finishTurnNoTools`. The Subagent RESULT is labelled by stop reason (success / `[subagent stopped: …]` note / structured-output error / error) and ALWAYS carries an `agentId: <childID>` trailer on EVERY terminal incl. error/timeout (mirroring `renderTeamResult`'s Team-id line) — the runtime-discoverability axis: the id must be where the MODEL reads it, not only on the client-only `subagent.*` events (it is the verbatim handle `InspectSubagent` loads by; children persist best-effort via `WithSubagentStore`, and `resume: <agentId>` continues a persisted child — default engine only, fresh fork + staleness note, `failed` not resumable, in-flight-guarded; the recovered session is re-homed onto the fork via the StateIdle-only `session.Session.Rehome`). Default (no `output_schema`) = free-text, unchanged. **Per-attempt vs cross-attempt limits:** each correction re-drive `Reopen()`s the child, which RESETS its `Counters`, so per-call `MaxTurns`/`MaxToolCalls` (and `WithChildLimits`) bound EACH ATTEMPT — a structured-output child can use up to `(1+defaultStructuredOutputRetries)×` its turn/tool budget across the whole call (bounded, not a runaway). The cross-attempt brake is the TOKEN budget: `driveChild` SUMS usage across drives and RE-PASSES the same `runOpts` (with the tighten-only `MaxRunTokens` override) to each `RunContentWith`, so `Deps.MaxRunTokens`/the per-call `max_tokens` accumulate and cap the whole call.

- **A free-text Subagent result is NEVER a silent "(subagent produced no summary)" on an EMPTY terminal (issue #48 / #152).** `driveChild`'s free-text path runs a TWO-STAGE recovery whenever the child ends on an EMPTY-terminal allow-set (`isEmptyTerminalStop` = `StopMaxTurns`/`StopMaxToolCalls`/`StopBudget`/`StopNoProgress`/`StopEndTurn`) with a BLANK finalText — the blank-finalText guard leaves a NORMAL text answer untouched. Stage 1 `salvageEmptyStop` (renamed from `salvageEmptyLimitStop`): ONE bounded wrap-up turn (`child.Reopen()` + `MaxTurns=1` pin + `salvageWrapUpPrompt`), with `ResetUsage` scoped to `StopBudget` ONLY (`StopNoProgress`/`StopEndTurn` must NOT ResetUsage — they did not stop on the ceiling, so the carried budget keeps braking the salvage turn). Stage 2 `digestChildActivity`, only if salvage was ALSO empty: the child's last non-empty `RoleAssistant` text walked backwards out of its own history (`clampRunes`-clamped, framed by `recoveredDigestPrefix`). **Framing discipline (UX): the stop reason is stated in exactly ONE place** — `renderSubagentResult` stamps `StopNoProgress` with the canonical note `[subagent stopped: ended without a final summary — treat as partial; resume it with the agentId above to continue]`; `recoveredDigestPrefix` states ONLY provenance + partial-ness + the resume hint (NOT the stop reason), so the note + prefix never double-state it and the prefix still reads standalone on the note-less empty-`StopEndTurn` path. The floor placeholder + the note both carry the resume next-action hint (the agentId trailer is on the result), so the result is never a dead end. The floor stands ONLY when both stages are empty, and even then the stop-reason note names WHY — never opaque. (The loop's `lastText` carries ANY text-bearing turn's text into the result, so for salvage to run the original drive produced no assistant text at all and the digest then finds none either — it is genuine belt-and-suspenders the live loop provably can't reach, internal-unit-tested.) Don't re-narrow the salvage trigger to limit/budget only, don't ResetUsage outside `StopBudget`, and don't restate the stop reason in the digest prefix.

- **Three DELEGATION observability families share a lifecycle, differ in aggregation — do NOT merge them.** `subagent.*` (flat fleet), `team.*` (coordinating roster), `parallel.*` (fan-out GROUP) all project the SAME redacted child-loop lifecycle, and the per-tool redaction is shared in EXACTLY ONE place — `agent.drainChildObserved` (the single chokepoint; `Parallel`'s `branchEmitter.branchTool` re-tags its `subagent.tool` emit into a `parallel.branch{branch_tool}`, copying only already-redacted fields). They differ only in their AGGREGATION (join/winner/fork-paths vs tasks/findings vs flat). `parallel.*` (`EvParallelStart/Branch/End` + `session.ParallelPayload`, proto `Parallel`=field 14, `toProtoParallel`) is METADATA-ONLY — gauntlet #7: NO branch args/results/message text crosses; it carries fork-root PATHS (handles already in the result text, not content). `parallel.end.Winner` is the REAL branch index (-1 for join=all/none); run Stop is the winner's for first/judge, omitted for all. **TRIP-WIRE: a 4th delegation family is the point to extract a shared `ChildActivity` value object — not before** (the doc-comment above the three payloads in `session/event.go` records this; a structural + a behavioral-sentinel test guard the no-leak). The `Parallel` ToolResult text (winner + preserved fork paths + per-branch `branch id:` lines for InspectSubagent) stays the MODEL's discovery channel; the events are CLIENT-only.

- **The filesystem is OPTIONAL per session (`CreateSessionRequest.profile = "no-fs"`, issue #55).** A no-fs session MUST route through the per-session engine factory (`needPerSession` includes the profile — the shared engine has FS tools baked in); its workspace is the honest `engine/adapter/nofs` Workspace registered as the CREATE-TIME per-session override (never memfs — silent write-loss; never the osfs factory on root ""); the workspace requirement is PROFILE-AWARE (default requires one, no-fs requires EMPTY, the combination rejected loudly); the catalog is EXACTLY default − {Read,Edit,Write,Grep,Glob,Bash,Parallel,SkillDraft} (`TestNoFSCatalogProfile`) — note WebSearch (issue #26), like WebFetch, is an outbound read present in BOTH profiles, so it is NOT in the excluded set; Subagent/Team children get the file-less `noFSChildCatalog` (memory six + WebFetch + WebSearch + global MCP), NO forkers/shell, and the honest posture (`WithSubagentNoFSNote`, `noFSPostureNote`). **Restart rehydration is NO LONGER no-fs-only (cloud-native Phase 1):** the per-session engine is rebuilt at the run-entry seam (`Service.StartRunContent`) for ANY session that `needsRehydration` — the no-fs profile OR a persisted provider/model selector OR an empty workspace — via `Service.rehydrateSession` (generalized from `rehydrateNoFSSession`), reading the PERSISTED `Profile`/`ProviderID`/`ModelID` labels off the loaded session so the rebuild is the SAME engine (no-fs catalog AND/OR same model), never the default-provider floor; a DEFAULT FS session (empty selector, default profile, non-empty workspace) does NOT rehydrate (it keeps the shared engine). Only the engine-rebuild trigger widened — the awaiting-approval mid-turn loop entry stays Phase 2. Details: IMPLEMENTATION-NOTES "Session profiles" + "Snapshot fidelity".

- **Guardrails (issue #27, the `modelhook` adapter): `PostToolUse` Block does NOT veto.** The tool has ALREADY run by the time the post hook fires (`dispatch.go` ~642-648 only emits an `EvHook` annotation), so enforce-blocking a bad INBOUND result rewrites it via `HookOutcome.Mutated` to `{content:"blocked by guardrail: …", is_error:true}` — NOT Block; only `PreToolUse` Block is a real veto. Allow/AllowAlways execute the call DIRECTLY (no re-run of preHook). `session.PendingAsk.HookOriginated` (SERIALIZED, `json:"hook_originated,omitempty"`) makes the awaiting-resume path (`resolvePendingCall`) SKIP preHook re-run on Allow (else a resumed guardrail ask re-blocks). AllowAlways arms a session "Allow & don't ask again" waiver (`modelhook.WaiverHolder`) via the new OPTIONAL `port.HookApprovalLearner` (type-asserted on `Deps.Hooks`, NEVER a `HookRunner` method — that'd break the API; all three engine additions are Added/minor); the waiver is in-memory, session-keyed (child-isolated), consulted in `Runner.check` BEFORE the LLM call, and is NOT plumbed to the Service (arming is in-loop from a human verdict, never a prompt scan). Posture-coupling is composition-only (`demoteForPosture`, the single posture→mode point): yolo demotes guardrails to advisory; strict/trusted/AUTO keep enforcing (under auto the interactive approve-once ask IS the auto-mode behaviour, gated on `Deps.Interactive` not posture). `AskApproval` is PreToolUse-only (ignored on Post; `mergeOutcomes` propagates it). ## Workflow

- Commit directly to `main`. End commit messages with the `Co-Authored-By` trailer. **Exception:** capability-scale agent work driven by the acceptance-plan spine (`/to-acceptance-plan` → `/plan-orchestrate`, ADR 0072) lands via PR on an accumulator branch — the orchestrator never merges to `main`; the human merge is the gate. Issue-scale work uses `/dev-pipeline`.
- Never `git add -A` — stage explicit paths.
- For smoke tests / scratch files, use the repo-local `.scratch/` dir (gitignored) — **not** `/tmp` or `mktemp`.
- **Changed a core `engine/` exported API?** The `api-compat` gate will fail until you run `task api:update`, commit the changed `engine/api/*.txt`, and note the change in `engine/CHANGELOG.md` classified per `engine/COMPATIBILITY.md` (Added = minor, Changed/Removed = breaking). See ADR 0037.
- **Changed any Markdown? Run `task generate` (or `task docs`) before committing — always.** `llms.txt` is generated and goes stale the instant docs change; never hand-edit it. `task docs` regenerates it (`task docs:llms`) and runs the strict link gate (`task docs:check`); `task generate` also refreshes it. The CI `docs` job will fail the PR on a stale `llms.txt` or any link regression — `matlatl check . --strict` (no broken links/anchors, orphans, unreachable, or ambiguous links; corpus config in `.matlatl.yml` / `.matlatlignore`). On a merge/rebase conflict in `llms.txt`, don't hand-merge — take either side and re-run `task docs:llms`.
- **Changed user-facing behavior (flags, config surface, deployment steps, APIs)? Update `user-docs/` (the public site content, rendered by the separate `website/` Docusaurus app — see `website/CLAUDE.md`) in the SAME PR, not "later."** This is a distinct tree from `docs/` above, and it is the weak link in the documentation lifecycle: the CI `user-docs` job (`task site:build`, Docusaurus `onBrokenLinks: 'throw'`) catches a broken link or an unreachable page, but nothing gates *staleness* — a shipped feature with zero user-docs mention is invisible to CI. Do this checklist before opening the PR: (1) does an existing `user-docs/what-you-get/*.md` or `user-docs/deployment/*.md` page cover the area you touched — if yes, extend it; (2) if no page covers it and the feature is operator-visible, add one short section (not a new page unless the topic is genuinely new surface); (3) `task site:build` locally to catch a broken link before CI does. Keep it lean: a short note plus a link out to the full `docs/usage/`/`docs/architecture/` reference is usually enough — `user-docs/` is not the place to re-explain implementation detail.
