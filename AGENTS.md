> open standard). `CLAUDE.md` is a **symlink to this file**, so Claude Code and any

A **headless agentic coding harness** in Go 1.26 (hexagonal/DDD): the streaming agent

## Operating as an agent in this repository

Be token-efficient by avoiding needless context, tool calls, and delegation—not by prematurely constraining useful work. When invoking `Subagent`, omit `max_run_tokens`/`max_tokens`, `max_turns`, `max_tool_calls`, and `timeout_ms` unless the user or task explicitly requests a bound. Omit `authority` too unless a task requires a deliberate, documented reduction of the child’s derived authority; an unnecessary `remaining_delegation_depth` or tool/filesystem restriction can prevent the delegation from running. Unnecessary limits can terminate a child after spending tokens without producing its deliverable.
For unfamiliar code, use `Grep` to locate symbols, then bounded `Read` calls (`offset` + `limit`); do not issue parallel full-file reads. Pass known ranges to a delegated worker and stop discovery once there is enough context for its next edit.

## Commands

**Always build through the Taskfile** — a bare `go build` in the repo root drops stray
binaries and is the wrong workflow.

```sh
task build              # → bin/mecated, bin/mecademo, bin/mecatui  (NEVER `go build` to repo root)
task test               # full suite, -race (root module + engine module + the GOWORK=off engine-standalone hygiene proof)
task test:golden        # refresh mecatui View/teatest goldens (-update) then re-run
task api:check          # api-compat gate: fail if the engine public surface drifts from engine/api/*.txt (also under task test)
task api:update         # regenerate engine/api/*.txt after an INTENTIONAL core-API change (commit + engine/CHANGELOG.md note)
task e2e                # LIVE e2e vs OpenRouter (real money, needs OPENROUTER_API_KEY exported) — NOT part of task test
task bench              # hot-path testing.B microbenchmarks (-benchmem) for benchstat; BENCHCOUNT=N overrides — NOT part of task test
task perf:scenarios     # OFFLINE whole-loop scenario benchmarks (perf-tracking Phase 2); MECATL_PERF_JSON=path for KPI JSON — NOT part of task test
task pgo:collect        # collect a PROVISIONAL offline CPU profile for PGO into .scratch/pgo/ — NOT committed; see perf-tracking Phase 4
task lint               # golangci-lint v2 + go vet (root module + engine module via --config ../.golangci.yml)
task vuln               # govulncheck reachable-vuln scan over BOTH modules (needs network for vuln DB) — NOT part of task test
task tidy               # tidy the go.mod files: root tidy, go work sync, then engine + provider/* GOWORK=off tidy
task generate           # regenerate contracts/gen from contracts/proto via buf
cd engine && go test ./agent/ -run TestFullCycle   # a single engine test (engine/ is its OWN module — run go test from engine/, not the repo root)
go run ./cmd/mecademo    # end-to-end demo, fully offline (mock provider)
```

> `engine/` is its **own Go module** (`github.com/stacklok/mecatl/engine`), kept in
> this repo as a MONOREPO via the committed `go.work` (`use ./` + `use ./engine`).
> The root module consumes it via `require …/engine` + `replace …/engine => ./engine`.
> External consumers importing `engine/agent` get only the engine's tiny dep closure

## Architecture (where things live)

Layered DDD; the package's layer is in CAPS. Design rationale lives in `docs/design/`.

Top-level shape: `engine/` is the importable core — the domain packages, the port
interfaces, the agent loop, and the in-tree reference adapters (`engine/adapter/*`) —
fully self-contained (tests included: nothing under `engine/` imports `internal/...`)
and intended to be importable as a library by external consumers; `internal/` holds
the heavy adapters (`internal/adapter/*`) and the composition layer (`internal/app`).
**`engine/` is its OWN Go module** (`github.com/stacklok/mecatl/engine`; ADR 0036),
consumed in-repo via the committed `go.work` and a root `replace …/engine => ./engine`;
its standalone dep closure is just `doublestar` + `robfig/cron` +
`github.com/goccy/go-yaml` + `x/net/html` + `x/sync` + test-only `goleak`, so an
external consumer's graph stays small. The repo stays a monorepo — the engine module,
the opt-in `provider/*` submodules (ADR 0093), and the root module all move in lockstep.

- `engine/session/` — DOMAIN: the `Session` aggregate (state machine), Conversation, the `ToolCall`/`ToolResult`/`Usage` value objects, the `Event` taxonomy.
- `engine/governance/` — DOMAIN: permission `Effect`/`Scope`/`Rule` + `Evaluator`, bash splitting/canonicalization, hook event types, and the five canonical model-visible untrusted-content framing/fence APIs (`UntrustedFence`, `WriteUntrustedBlock`, `FenceUntrusted`, `NeutraliseFraming`, `NeutraliseDelegationResult`). **Session-free** (`session` imports it, never the reverse). `engine/agent/fence.go` retains only the agent-specific `StripLoneCodeFence` parser and private delegation-result wrapper.
- `engine/tool/` — DOMAIN: `Tool`/`ToolSpec`/`Catalog` **and** the `FileSystem`/`Workspace` interfaces (see gotcha), plus the `SkillSource` port (`skillsource.go`): skills cross it as LOGICAL BUNDLES — identity/metadata (`SkillMeta`), body, payloads by logical name (`SkillAsset`, `ValidSkillAssetName`) — NEVER a path/dir/root. The `Skill` tool consumes that port directly: `{name}` returns instructions + a logical asset inventory; `{name,asset}` reads one bounded textual asset on demand. Assets are never materialized, exposed as workspace read roots, or implicitly executable. The filesystem adapter's paths remain private to that adapter, plus the `AgentDefSource` port (`agentsource.go`): the WHOLE `AgentDef` value object lives here (no locator field; `Origin` is a tier label, never a location; `AgentMCPServer.Headers` is SECRET-SHAPED — never logged/projected), SNAPSHOT semantics — where a def came from is the agents adapter's NON-PORT detail channel (`agents.Discovered.Detail`/`Registry.Detail`). A def's `memory:` head (issue #33, `AgentDef.Memory` = `user`/`project`; READ-ONLY v1, write path deferred) rides the cache-stable `Role`/StablePrefix via `agentPromptConfig` (fenced UNTRUSTED DATA), NEVER per-turn; the **project** tier is `cfg.TrustProject`-gated (same fold as project-tier defs) and the def name is path-sanitized (`safeAgentMemoryDir`) — resolved to a concrete dir ONLY in composition (`resolveAgentMemoryHead`).
- `engine/prompt/` — DOMAIN: two-layer prompt assembly + AGENTS.md/CLAUDE.md discovery; the turn-0 `InstructionAssembler` chain and its consumer-local ports (`MemoryIndexSource`, `SoulSource`, `UserModelSource`, `RulesSource` (issue #329, the `.claude/rules` discovery port — eager v1, `paths:` as a model-applied condition; ADR 0081), and `CommandSource` + `SourceExpander` — LIVE-semantics slash commands reusing the SAME parse/strip/substitute path as `DirCommandExpander`, so a template expands byte-identically whichever backend serves it; `ValidCommandName` is the ONE invocation-grammar validator). Trust/provenance decisions live in composition, not here.
- `engine/port/` — the PORT interfaces the loop consumes (`LLMProvider`, `SessionStore`, `HookRunner`, `PermissionPolicy`, `Clock`, `Diagnostics`, `ToolCallRecorder`, `EventSink`).
- `engine/agent/` — APPLICATION: the loop (`Engine`/`Run`), dispatch, permission pause/resume, compaction, the Subagent delegation tool, the agent-team `Supervisor`/`TeamTool`. Read-only subagents (Subagent default + read-only team members) run their Bash in an isolated git worktree via a sandboxed runner, TRUST-GATED (issue #40): an untrusted workspace nils the runner — no read-only subagent/member shell, honest Spec note — while Mutating members/Parallel branches keep their HARDENED shells (`buildForceCopyRunner`: force-copy forking runs NO git, so the fork-time checkout RCE the gate closes can't fire there; their run-time git over the verbatim-copied untrusted `.git` is the accepted main-session-parity residual). A `mode:"read-write"` Subagent (ADR 0077, superseding 0040's writable path) is DIRECT-WRITE: no fork, no copy, no merge — it runs Edit/Write/Bash DIRECTLY against the REAL parent workspace (the MAIN session's command runner, main-session parity), exactly as the main agent does, and git is the rollback layer; it stays mutate-serial via the `parentMutatingCaller` seam (now decoupled from any merger) and is NOT isolated (`isolated:false` removes the A2 auto-approve). Default-wired (no flag), per-call default still read-only; a crashed/cancelled child can leave PARTIAL edits (recoverable via git). Scope is the serial Subagent ONLY — Parallel branches and mutating members keep force-copy + serialized merge for genuine concurrency. See `docs/adr/0014-agent-teams.md`, `docs/adr/0077-direct-write-subagent.md`, and the subagent-shell gotcha.
- `engine/adapter/` — the REFERENCE adapters that travel with the importable core (offline tests + sane defaults for any engine consumer): `mockllm`, `memfs`, `memstore`, `sessnap`, `eventsource` (the reference event-log→`*session.Session` fold for event-sourced `SessionStore.Load`, ADR 0038), `permpolicy`, `permstore`, `wallclock` (the production `port.Clock`), `fstools` (the correctness/security-critical FS tool BODIES — Read/Edit/Write/Grep/Glob + the optional Bash — graduated into the importable module per issue #269 so consumers get Edit's read-before-edit/exact-match/uniqueness invariants by import; the root `internal/adapter/tools` re-exports them via alias), `webfetch` (the bounded, SSRF-resistant public HTTP(S) text fetch tool; DNS-pinned dialing, per-hop redirect validation, 5 MiB raw/decompressed limits, and hostile-HTML text extraction; the root tools package re-exports it), `search` (the graduated web-search tool body + Exa/HTTP/SearXNG providers + offline fake, per #363; the root `internal/adapter/tools` re-exports it via alias), `agentfs` (the filesystem `.claude/agents` agent-def discovery adapter graduated per #328; the root `internal/adapter/agents` re-exports it via alias), `skillfs` (the read-only `.claude/skills` discovery core + Skill tool body graduated per #328; the writable SkillDraft half stays in root `internal/adapter/skills` and reaches the core via alias), `rulesfs` (the `.claude/rules` discovery adapter, issue #329; the root `internal/adapter/rules` re-exports it via alias), `fsconformance`, `memconformance`, `storeconformance`, `sourceconformance` (SkillSource/SoulSource/AgentDefSource/CommandSource/RulesSource suites + the canonical fixtures `Fixture`/`AgentFixture`/`CommandFixture` and their `New*FixtureSource` references). Stdlib + engine-only (memfs adds doublestar); strict depguard allowlists; core PRODUCTION code still must not import them (test files may).
- `provider/` — the REAL LLM-provider adapters as OPT-IN Go submodules (ADR 0093): `anthropic` (native Messages API), `openai` (Responses API), `openaichat` (Chat Completions API), and `ssefilter` (the shared SSE keepalive filter). Each is its OWN Go module (`github.com/stacklok/mecatl/provider/<name>`) requiring the engine module + its SDK (+ `provider/ssefilter` for the openai-go family) — a consumer `go get`s exactly the provider(s) it wants and pulls only that SDK, never the root module. Released under `provider/<name>/vX.Y.Z` tags; the `v*` image trigger never fires on them. See `docs/adr/0093-provider-modules.md`.

## The layering rule (the thing to get right)

Dependencies point **inward only**, machine-enforced THREE ways (all run under `task lint`/`task test`): the **depguard allowlist** in `.golangci.yml` (per-file — each core tier is `list-mode: strict` allowing only `$gostd` + the exact core packages it imports, with an `os` deny on top; a NEW heavy-adapter import is rejected by default; the engine module shares THIS config via `--config ../.golangci.yml`, no engine-local copy); the **DAG test** in `engine/arch/layering_test.go` (whole-graph — transitive direction + cycle detection, which the per-file depguard cannot express); AND the **module boundary itself** (ADR 0036) — the engine is its own Go module, so a stray engine→host-repo import breaks the `GOWORK=off` standalone build outright (`task test:engine-standalone`). `engine/team` is part of the core (agent imports it).

- Domain (`session`, `prompt`, `governance`, `tool`), `engine/team`, and `engine/agent` must **never** import an adapter, `contracts/gen`, `os`, the OpenAI/Anthropic SDKs, or gRPC.
- `engine/port` imports only domain + stdlib. `engine/agent` imports only domain + `port` + `team` (+ stdlib + `golang.org/x/sync/errgroup`) — adapters are injected. (Core **test** files may import the `engine/adapter/*` reference adapters — `memfs`/`mockllm`/`permpolicy`/… — to run offline; the depguard core rules exclude `$test`, and the DAG test reads non-test imports only. The engine tree is fully self-contained, tests included: nothing under `engine/` imports `internal/...` — integration tests that need a heavy adapter live next to that adapter under `internal/adapter/`.)
- Concrete adapters meet ports **only** in the composition layer — `internal/app` and the `cmd/` mains. No DI framework; explicit constructors. Keep wiring in `internal/app`, not in domain/`port`/`agent`.

## Things That Will Bite You — implementation invariants

This section is a contract for **changing mecatl's code**. Preserve the documented behavior and defaults when modifying the implementation; it is not operating guidance for an agent using mecatl.

- **`FileSystem`/`Workspace`/`Environment` live in `engine/tool`, NOT `engine/port`.** Moving them to `port` creates a `port↔tool` cycle (`port.LLMRequest` references `tool.ToolSpec`; `Tool.Execute` takes an `Environment`). Leave them in `tool`. Skill assets do NOT widen the Workspace: the `Skill` tool reads one bounded textual payload directly from the path-free `SkillSource` when called with `{name,asset}`. Do not restore skill-derived workspace read roots, base-directory headers, or remote asset materialization; Bash needing real files is not a reason to place every bundled reference on disk or make it executable. **ADR 0208 version protocol:** `FileVersion` is opaque; agent-facing Read records the exact `ReadVersion` token (RecordRead does NO I/O), new-file Write uses create-only `CreateFile`, and Edit/existing-file Write compare `RecordedVersion` with a current read then finish with conditional `ReplaceFile`. Public `tool.Workspace` exposes NO unconditional Write and there is NO empty/AnyVersion overwrite sentinel; concrete adapters may retain Write only for bootstrap/setup outside the Tool capability. `RecordRead`/`RecordedVersion` key with I/O-free lexical Clean/Rel only — never Lstat/EvalSymlinks/RPC; ordinary abs/relative forms converge and physical symlink aliases may safely false-negative. The ledger belongs to the live Workspace/Environment instance and resets whenever the default factory rebuilds that Workspace (including the next user run) or the process restarts; `Service.sessionEnvironments` remains OVERRIDES-only (no default cache — each override is a COMPLETE shell-less/shell-bearing `Environment` the creator owns with an accurate ref; the Service does NOT guess a ref or runner from an override's presence). The base atomicity guarantee covers concurrent calls through the same live Workspace/backend handle; osfs additionally canonicalizes the physical mutation identity (existing full target; missing parent+basename), serializes cooperating same-target mutations process-wide across Workspace instances, and uses confined `O_CREATE|O_EXCL` for create. Arbitrary POSIX writers do not participate in local CAS. ACP may classify a missing buffer ONLY from structured `rpcError.Message` after removing the exact confined requested path (bare/common quoted forms), then whole-message matching a narrow absence vocabulary; never scan marker substrings. Generic transport/decode faults and structured permission/unavailable messages fail closed even when the echoed path says `not found`/`enoent`. **The execution-environment seam (ADR 0211, issue #462) is IMPLEMENTED:** `Tool.Execute` takes a `tool.Environment` (identity `session.EnvironmentRef{Kind, ID}` + NON-NULL `Workspace` + OPTIONAL bound `CommandRunner`); `CommandRunner.Run`/`CommandStreamer.RunStreaming` LOST the per-call workdir (a runner is BOUND to one namespace at construction); `tool.EnvironmentForker` replaces `tool.WorkspaceForker` (Fork returns a complete child `Environment` whose Workspace and runner share the child namespace — `childEnv` derives ref ID and bound runner root from `ws.Root()`, so the worktree-failure→copy fallback can never bind to the discarded reservation); `tool.EnvironmentMerger` replaces `tool.ForkMerger` (Merge receives child/parent `Environment`s, no forkRoot string). Composition wires the forker's bound-runner builder (`forker.WithRunner`, the same envscrub/gitenv hardening as the parent runner); the Service binds the main `CommandRunner` + a `CommandRunnerFactory` for worktree-bound sessions, and override creators (ACP, no-fs) register complete `Environment`s via `SetSessionEnvironment` with accurate refs (ACP is a LOCAL shell-less namespace, NOT a guessed no-fs). `EnvironmentRef` is an IN-PROCESS identity in phase 2 — not yet a snapshot field (persistence/remote transport deferred to phase 3). A direct-write Subagent uses the PARENT Environment; read-only/copy/worktree branches and Team use the CHILD Environment. No production remote transport yet (phase 3). **ADR 0291 supersedes the former public-path/lazy-stamping posture:** `session.EnvironmentRef{Kind, ID, Revision}` is the ONLY durable runtime identity and is persisted exactly in `sessnap.Snapshot`; `Session.Workspace` and snapshot `Workspace` do not exist. Every created session has a valid exact ref before persistence; zero refs and legacy duplicate placement state are rejected, never inferred, adopted, or stamped later. Public Harness/HTTP/client surfaces expose only bounded display metadata, never a filesystem path or exact private ref. Trusted snapshots and driver storage may carry the exact private ref. Run entry calls the server-owned placement provider's exact `Reattach`; mismatch, unavailable revision, nil Workspace, or missing provider fails closed with no default fallback. ACP cwd is only a local assertion against trusted configured placement.**
- **Every agent-facing shell runs with a SECRET-scrubbed env (security "Finding B") — don't reintroduce the `os.Environ()` passthrough.** The main + sandboxed/force-copy command runners + fork-time git get `internal/adapter/envscrub.Scrub(os.Environ())` (the hardened ones as `gitenv.Scrub(envscrub.Scrub(...))`) via `osfs.WithCommandEnvList`, so under posture `auto`/`yolo` the model can't `echo $OPENROUTER_API_KEY` / `cat /proc/self/environ`. `envscrub` is a stdlib leaf with a precise DENYLIST (the exact harness creds — provider/websearch/`MECATL_*`/`GH_TOKEN` — plus secret-shaped `*_API_KEY`/`*_TOKEN`/`*_SECRET`/`*_PASSWORD`/`AWS_*`/`AZURE_*`), NOT an allowlist (the toolchain `PATH`/`HOME`/`GOPATH`/… must survive). ONE policy across all runners; oracle (mutation-tested) is `internal/app/command_runner_secret_scrub_test.go`. `gitenv.Scrub` only ever did GIT_*/PAGER — it is NOT a secret scrub.
- **`port.PermissionPolicy` is implemented in `engine/adapter/permpolicy`, not `governance`** — `governance` can't import `session` (cycle), so the session-aware policy is an adapter over the session-free `governance.Evaluator`.
- **A `session.ToolResult` (and every producer-influenced string) must hold valid UTF-8 before it reaches the protobuf mapper (issue #402).** A tool can hand back arbitrary bytes (a command's stdout — e.g. BSD `cat -t` mangling an em dash into an orphaned `\xe2` lead byte — a file's contents, an MCP server's text), and a protobuf string field REJECTS invalid UTF-8 at marshal time, which killed the live Converse stream with `codes.Internal`. (The durable JSON log survives because `encoding/json` already substitutes U+FFFD — which is why replay can look healthy while the live stream dies.) Defense in depth, TWO layers: (a) the SEMANTIC repair — `session.RepairToolResult` (stdlib-only, in the domain leaf so both layers can import it) normalizes `Content` + the textual fields of every `Parts` block (`Text`/`Name`/`Title`/`Description`/`URL`/`LastModified`/`Audience`), leaving binary `Data` and the `MIMEType` token byte-exact; it is applied at the loop's effective-payload choke point in `engine/agent` `execute` AFTER PostToolUse and BEFORE recorder/emit/record, so the recorded == streamed == model-view invariant holds with the SAME repaired text. Do NOT move it into the `NewToolResult*` constructors (that smears the single-choke-point invariant across every caller, incl. replay/test paths). **`execute` is not the ONLY producer that reaches recorded state**: a PreToolUse hook is an operator-deployed SUBPROCESS whose `HookOutcome.Message` is its raw stdout (`hookexec` `blockMessage`, TrimSpace only) and whose `Mutated` is rewritten args JSON — and `json.Valid` ACCEPTS invalid UTF-8 inside a string literal. A block becomes a `NewToolError` at FOUR sites (`runOne`, `runReadBatch` Phase 1, both `resolvePendingCall` arms), none of which call `execute`, so both values are repaired ONCE in `preHook` right after `Hooks.Run` — the single point they arrive, never at the four consumers. Pinned by `TestPreToolUseHookOutputIsRepaired`. (b) the MECHANICAL backstop — `internal/adapter/server/mapper.go` runs every producer-influenced string through `session.ToValidUTF8` (the `valid` alias) at the assignment, so a malformed string from ANY future/custom producer (replayed history, child-output previews, MCP/OS metadata) can never fail marshaling again; harness-authored constants/machine tokens (ids, kinds, stops, enums) are skipped. Stage 1 `salvageEmptyStop` (renamed from `salvageEmptyLimitStop`): ONE bounded wrap-up turn (`child.Reopen()` + `MaxTurns=1` pin + `salvageWrapUpPrompt`), with `ResetUsage` scoped to `StopBudget` ONLY (`StopNoProgress`/`StopEndTurn` must NOT ResetUsage — they did not stop on the ceiling, so the carried budget keeps braking the salvage turn). Stage 2 `digestChildActivity`, only if salvage was ALSO empty: the child's last non-empty `RoleAssistant` text walked backwards out of its own history (`clampRunes`-clamped, framed by `recoveredDigestPrefix`). **Framing discipline (UX): the stop reason is stated in exactly ONE place** — `renderSubagentResult` stamps `StopNoProgress` with the canonical note `[subagent stopped: ended without a final summary — treat as partial; resume it with the agentId above to continue]`; `recoveredDigestPrefix` states ONLY provenance + partial-ness — NEITHER the stop reason NOR the next action, because the note owns both and the two render one after the other (the prefix used to duplicate `treat as partial; resume it with the agentId above to continue` byte-for-byte, and a model reading one imperative twice can't tell it from two); it still reads standalone on the note-less empty-`StopEndTurn` path, which is a BENIGN clean end and owes no next action (the agentId trailer is on the result either way). The floor placeholder + the note both carry the resume next-action hint, so the result is never a dead end. The floor stands ONLY when both stages are empty, and even then the stop-reason note names WHY — never opaque. (The loop's `lastText` carries ANY text-bearing turn's text into the result, so for salvage to run the original drive produced no assistant text at all and the digest then finds none either — it is genuine belt-and-suspenders the live loop provably can't reach, internal-unit-tested.) Don't re-narrow the salvage trigger to limit/budget only, don't ResetUsage outside `StopBudget`, and don't restate the stop reason OR the next action in the digest prefix.

- **Three DELEGATION observability families share a lifecycle, differ in aggregation — do NOT merge them.** `subagent.*` (flat fleet), `team.*` (coordinating roster), `parallel.*` (fan-out GROUP) all project the SAME redacted child-loop lifecycle, and the per-tool redaction is shared in EXACTLY ONE place — `agent.drainChildObserved` (the single chokepoint; `Parallel`'s `branchEmitter.branchTool` re-tags its `subagent.tool` emit into a `parallel.branch{branch_tool}`, copying only already-redacted fields). They differ only in their AGGREGATION (join/winner/fork-paths vs tasks/findings vs flat). `parallel.*` (`EvParallelStart/Branch/End` + `session.ParallelPayload`, proto `Parallel`=field 14, `toProtoParallel`) carries the same clamped + control-byte-scrubbed, client-only `Text`/`Detail`/`InnerKind` previews as the others (ADR 0079 two tiers; superseding the former metadata-only contract for `parallel.*`/`subagent.*`) — gauntlet #7 unchanged, the parent Conversation still never sees child content; it carries fork-root PATHS (handles already in the result text, not content). `parallel.end.Winner` is the REAL branch index (-1 for join=all/none); run Stop is the winner's for first/judge, omitted for all. **TRIP-WIRE: a 4th delegation family is the point to extract a shared `ChildActivity` value object — not before** (the doc-comment above the three payloads in `session/event.go` records this; a structural + a behavioral-sentinel test guard the no-leak). The `Parallel` ToolResult text (winner + preserved fork paths + per-branch `branch id:` lines for InspectSubagent) stays the MODEL's discovery channel; the events are CLIENT-only. **A FAILED child's CAUSE has exactly ONE composer (issue #319):** the loop puts the real failure detail on `session.ResultPayload.Error`, `handleChildEvent`→`drainChildObserved`→`driveChild` thread it out (`drainChild` KEEPS its 2-value signature — five callers don't want it), and `agent.subagentErrorBody(cause, final)` composes the `StopError` body — cause FIRST (the actionable half; the params are ordered as they RENDER, because both are `string` and a positional swap compiles into exactly the bug #319 fixed), the child's last assistant text demoted to clamped `Last activity before the failure:` context. Being the one composer it is also the one BOUNDER — BOTH halves are clamped there (the body is recorded into the PARENT's persisted conversation, so the parent re-pays for it every turn), and its floor wording is caller-NEUTRAL (`failed without producing a summary` — the Subagent path prefixes `Subagent: `, the Parallel path renders it under a `=== branch-N [FAILED] ===` header). `renderSubagentResult`/`renderWritableSubagentResult` AND `parallel.go`'s `res.failReason` all call it; do NOT grow a second policy, and do NOT re-render `final` as the error (that WAS the bug: a chatty child's last sentence was presented as the failure reason). `session.SubagentPayload.Cause` mirrors it on `EvSubagentEnd` ONLY, normalised (whitespace-collapsed then clamped to `maxSubagentCausePreview` 400) by `subagentCausePayload` via the ONE `subagentEndEvent` constructor every emit site builds through — there are THREE sites (foreground, background terminal, and `driveBackground`'s pre-run `endOnError` — a fork/session-build failure is a `StopError` terminal too, and the background path has NO other channel for its why), on the wire as `Subagent.cause`=field 17 → `toProtoSubagent` → the mecatui fleet pane AND the ACP `subagent finished` line (both projections surface it — don't let one drift). `ParallelPayload` deliberately gains NO field (the branch failure already reaches the model via the `Parallel` ToolResult text). `salvageEmptyStop` still never sees `StopError` (`isEmptyTerminalStop` excludes it) — do not "helpfully" add it. **The cause is ALSO durable on the CHILD snapshot (issue #332, the `Permanent`-analog):** `session.Session.RecordLastError`/`LastError` persist the terminal cause on a `failed` session (cleared on `Recover`/`resetToIdle`), normalised to one line + clamped to 400 runes (mirroring `subagentCausePayload` so the snapshot and the event agree byte-for-byte), round-tripping on `sessnap.Snapshot.LastError` + `RestoreState`'s trailing `lastError` param (additive, `omitempty`). `driveBackground`/`run()` call `RecordLastError` BEFORE `persistChild` on BOTH paths, so the snapshot is the single durable cause source independent of the parent's `subagent.end` emit race — a background child's end-emit can lose the race with the run-end seal (`drainChildren`'s `abortEmits`), so without the snapshot field the cause would be lost when the event never reaches the parent stream. No proto change (the cause already rides `SubagentPayload.Cause`/`TeamPayload.Cause` on the wire). **EVERY delegation-result arm neutralises its model-influenced text, not just the failed one** (CWE-1427/LLM01): `agent.neutraliseChildText` is applied ONCE at the top of `renderSubagentResult` (covering the success/limit/cancel/structured arms — a read-only child has WebFetch/WebSearch/Read, so a hostile page it summarises reaches the COMMON path, and the success arm stamps the SAME `agentId:` trailer + bracketed notes around child prose), again inside the Parallel-shared `subagentErrorBody`, and at the ONE point `parallel.go` assigns `res.summary`; the schema-VALIDATED structured payload is the one deliberate exemption (no raw line break can exist inside it, and whole-line redaction would corrupt the deliverable). `NeutraliseFraming` NORMALISES before matching (fold every line terminator incl. CR/U+2028/U+2029/NEL/VT/FF, strip Unicode `Cf`/`Cc` via `canonLine`) so ONE invisible character or an exotic separator can no longer hide a forged header — fix it at the MATCHER, never per marker; `neutraliseChildText` adds the FLOOR that keeps whole-line redaction honest (a wholly-redacted value comes back `%q`-quoted, because erasing a genuine one-line provider error re-creates the opaque failure #319 abolished); and `framingHeader`'s delegation entries are kept COMPLETE by `TestDelegationResultMarkersCannotBeForged`/`TestParallelJoinMarkersCannotBeForged`, which feed each renderer's OWN output back through it as a forged body — a new marker line with no entry fails a test rather than shipping a hole. **The `StopError` resume hint (#318) has ONE gate, `subagentResumeHint(resumable)`, and two reasons to stay silent:** a store-less `SubagentTool` (`t.store == nil`, `validateResume`'s first precondition) must NOT advertise a `resume:` it will then refuse — same discoverability rule that keeps the hint out of the Parallel path — and the WRITABLE arm suppresses it because `renderWritableSubagentResult` owns a single combined next-action (`writableSubagentFailedNote`: resume-on-top-of-the-partial-edits OR discard-them, "Do not do both"). Two independent imperatives let a model do both, discarding the edits and then resuming a child `resumeWritableNote` greets with "STILL IN PLACE". The hint's WORDING is mode-accurate: conversation preserved, WORKSPACE not (the child ran in a throwaway checkout, so files it wrote are GONE) — the old "continue where it left off" contradicted the `resumeStalenessNote` the resumed child actually receives, and the claim as worded holds whether the resume returns read-only or is upgraded to `read-write`. **The per-call TIME-BUDGET terminal has the SAME shape** via its own `subagentTimeoutNote(writable, resumable)` gate (four cells mirroring `subagentResumeHint`: `subagentTimeoutResumeHint` / `writableSubagentTimeoutNote` / `writableSubagentPartialNote` / silence), used by BOTH the foreground and background sites: it was the last failure path with no next action, and a timed-out child lands `StateCancelled` which resume has always recovered. Its wording is its OWN (not a `StopError` reuse) because the child ran out of clock, not competence, and the fix has a nameable knob — a larger `timeout_ms`.

## Workflow

- Substantive issue and capability work uses the single acceptance-plan spine (`/to-acceptance-plan` → `/plan-orchestrate`, ADR 0295). Scale the plan down to one compact scenario and task for focused work; do not manufacture complexity. The orchestrator lands plan + work through one accumulator PR, never merges to `main`, and the human merge is the gate. Only trivial or mechanical edits may commit directly to `main`. End commit messages with the `Co-Authored-By` trailer.
- Never `git add -A` — stage explicit paths.
- For smoke tests / scratch files, use the repo-local `.scratch/` dir (gitignored) — **not** `/tmp` or `mktemp`.
- **Changed a core `engine/` exported API?** The `api-compat` gate will fail until you run `task api:update`, commit the changed `engine/api/*.txt`, and note the change in `engine/CHANGELOG.md` classified per `engine/COMPATIBILITY.md` (Added = minor, Changed/Removed = breaking). See ADR 0037.
- **Changed any Markdown? Run `task generate` (for contract changes) or `task docs` before committing — always.** `task docs` refreshes the generated configuration reference and runs the strict link gate (`task docs:check`); `task generate` also refreshes the configuration reference. The CI `docs` job fails on configuration-reference drift or any link regression — `matlatl check . --strict` (no broken links/anchors, orphans, unreachable, or ambiguous links; corpus config in `.matlatl.yml` / `.matlatlignore`).
- **Changed user-facing behavior (flags, config surface, deployment steps, APIs)? Update `user-docs/` (the public site content, rendered by the separate `website/` Docusaurus app — see `website/CLAUDE.md`) in the SAME PR, not "later."** This is a distinct tree from `docs/` above, and it is the weak link in the documentation lifecycle: the CI `user-docs` job (`task site:build`, Docusaurus `onBrokenLinks: 'throw'`) catches a broken link or an unreachable page, but nothing gates *staleness* — a shipped feature with zero user-docs mention is invisible to CI. Do this checklist before opening the PR: (1) does an existing `user-docs/building/what-you-get/*.md` or `user-docs/building/deployment/*.md` page cover the area you touched — if yes, extend it; (2) if no page covers it and the feature is operator-visible, add one short section (not a new page unless the topic is genuinely new surface); (3) `task site:build` locally to catch a broken link before CI does. Keep it lean: a short note plus a link out to the full `docs/usage/`/`docs/architecture/` reference is usually enough — `user-docs/` is not the place to re-explain implementation detail.
