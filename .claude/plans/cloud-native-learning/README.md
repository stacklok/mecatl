# Cloud-native learning orchestration

Accumulator: `acc/cloud-native-learning`

This graph delivers the six acceptance scenarios in dependency order. It fixes verified explicit intent first, establishes the authoritative attempt domain and durable repositories, reconstructs bounded evidence, lands the explicit worker slice, extends distributed authority through proposal/skill drivers and claim fencing, converges replica catalogs, adds authorized controls, and only then replaces process-local automatic accounting with a distributed ledger. Documentation and generated surfaces are reconciled by the final single-writer task.

## DAG waves

1. Explicit intent: `01`, then `02`.
2. Attempt domain: `03`; repository contract `04`; conformance `05`; then reference and durable adapters `06`, `07`, `08`; admission binding `09`.
3. Evidence and worker core: `10`; then `11`; reconciliation `12`; explicit vertical slice `13`.
4. Distributed downstream repositories: `14`, `15`; shared drivers `16`; conformance integration `17`.
5. Claim fencing: `18`.
6. Replica catalog convergence: protocol `19`; hydration `20`; partition uncertainty `21`.
7. Authorized state/control: API projection `22`; controls `23`; driver ownership `24`; no-watch guard `25`.
8. Distributed automatic controls: ledger domain `26`; durable global accounting `27`; crash reconciliation `28`; weighted lifecycle wiring `29`; capability claims `30`.
9. Documentation/generated integration: `31`.

No task maps a GitHub issue. Every task starts pending and is merged only through the accumulator.
